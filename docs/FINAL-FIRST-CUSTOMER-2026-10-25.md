```

  select move_state('<pv-one 에게 배정된 신청>','accepted','{}')

```

| 무엇이 나빠지나 |
|---|
| 감사 기록에 **남이 수락한 것**으로 남습니다 (§8 의 뜻이 사라집니다) |
| 경쟁 업체가 남의 건을 협의 · 계약까지 밀 수 있습니다 |
| **고객 쪽도 같습니다** — 고객 역할은 취소 · 보류를 갈 수 있는데 **자기 신청인지**를 안 봐서 남의 접수를 취소할 수 있었습니다 |

⚠️ **RLS 로는 안 막힙니다.** 그 업체는 그 신청을 **읽지는** 못하지만
(`request_assigned`), `move_state` 는 security definer 라 RLS 를
지나갑니다 — **"읽기만 막아 두면 된다" 가 아닌 자리**였습니다.

⚠️⚠️ **함수를 다시 쓰지 않고 트리거로 얹었습니다.** `move_state` 는
0004 에서 만들고 0007 이 다시 썼습니다 — 또 베끼면 **세 벌**이 되고,
이 저장소는 같은 규칙을 두 곳에 적어 어긋난 사고를 여러 번 겪었습니다.

## 13. 첫 고객을 받아도 되는지에 대한 최종 판단

### **아직 아닙니다** — 코드가 아니라 **설정과 정보**가 빕니다

```
오늘 그대로 첫 고객이 신청을 누르면 —
  접수는 **슬랙으로 갑니다** (INTAKE_WEBHOOK_URL 이 켜져 있습니다)
  접수번호는 **안 나옵니다** (저장할 DB 가 안 켜져 있습니다)
  /admin 접수 목록은 **안 그려집니다** (로그인이 auth:false 입니다)
  배정할 업체는 **0곳입니다**
  푸터에는 **사업자 정보가 없습니다**
```

**즉 신청을 잃지는 않지만**(슬랙에 있습니다) **그 뒤를 시스템이 못
받습니다** — 사람이 채널을 보고 전화하는 것까지입니다.

### 이 차례로 하시면 **첫 고객을 받을 수 있습니다**

```
① 사업자 정보 여덟 칸          (대표님 · 10분)
② 0008~0019 돌리기 + verify     (대표님 · 35분)
③ 환경변수 + 다시 배포          (대표님 · 15분)
④ 첫 관리자 SQL                (대표님 · 2분)
⑤ main 에 합치기 = 배포         ⚠️ 대표님 승인 뒤
⑥ 제휴업체 한 곳 등록 + 계정 연결 + 배정 가능 + 수수료 정책
⑦ **직접 접수 한 건을 넣어 보고 ⑥ 의 업체까지 배정해 보기**
   → 여기까지 되면 첫 고객을 받아도 됩니다
```

⚠️⚠️ **⑦ 을 건너뛰지 마세요.** 이 저장소에서 "검사는 다 초록인데
실제로는 안 되던" 자리가 여러 번 있었습니다 — `api/me.js` 가 신청
`id` 를 안 주던 것 · `move_state` 가 남의 건을 밀 수 있던 것 ·
푸터 칸 이름 넷. **검사로 안 보이는 것은 눌러 봐야 압니다.**
