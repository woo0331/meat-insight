### 고치다 **찾은 것 넷** (지시서에 없던 고장)

| 무엇 | 왜 나쁜가 |
|---|---|
| `AM_PICK_EASY.equip` 이 **"주방 기계 · 설비"** | 업종 열넷 **전부**에 같은 글자로 나옵니다 — 미용실 · 헬스장 · 학원 · 사무실 사장님께는 남의 말입니다 |
| 창업 고르개에서 **"간판" · "세금" · "포스" 가 0건** | 고르는 단위가 분류 열넷이라 그 낱말이 이름에 없었습니다. 손님은 분류 이름을 모르고 **하려는 일**을 칩니다 |
| `pickFind()` 가 접힌 목록 id 를 **박아** 두고 있었음 | 창업에 찾기 칸을 붙이자 "찾았다" 고만 하고 아무것도 안 열렸을 자리입니다 |
| 하위 카드에 **분류가 안 보임** | "가구" · "폐업신고" 만 있으면 어느 분야 것인지 안 보이고 바구니에서 섞입니다 |

⚠️ 그리고 **제가 만든 사고 하나**를 적어 둡니다 — 새 업종 고르개에
`id="st-ind"` 를 주었는데 바로 아래 "업종별로 자세히" 펼침 목록이 그
id 를 쓰고 있어 **겹쳤습니다**. 흐름 검사가 잡았고 `st-indsel` 로
고쳤습니다. 이 저장소가 클래스 이름 겹침으로 세 번 겪은 사고의 id 판입니다.

### 새로 넣은 빌드 가드 여섯 — **전부 되돌려서 잡히는 것을 확인했습니다**

1. 업종 추천이 **그 업종 목록에 없는 분류**를 가리킴
2. 없는 업종 key · **`기타`(etc)에 추천을 적음** · 개수가 여섯이 아님
3. 빠른 선택이 **분류**(묶음 머리와 같은 칸이 됩니다 · PART 16-12)
4. 빠른 선택이 없는 id · 개수 · 겹침 · 내려놓은 서비스
5. **쉬운 이름에 업종이 드러나는 말**(주방 · 미용 · 헬스 …)
6. FAQ 문답이 **없는 카테고리**를 가리킴
