# Q1. 신청서를 제출하면 **정확히 어디에 저장되고 누구에게 가는가**

## 오늘 (DB 미설정 · 지금 운영 중인 상태)

```
손님이 /quote 에서 제출
  → POST /api/quote
  → ① 저장 블록을 **건너뜁니다** (dbReady() 가 거짓)
  → ② deliver() 가 INTAKE_WEBHOOK_URL 로 POST  ← 슬랙 워크플로
  → ③ 성공하면 200 { ok:true }   ⚠️ 접수번호 **없음**
```

| 무엇 | 지금 |
|---|---|
| **저장되는 곳** | **없습니다.** `api/quote.js` 가 `dbReady()`(= `SUPABASE_URL` + `SUPABASE_SERVICE_KEY`)가 거짓이면 `request` 저장 블록을 통째로 건너뜁니다 |
| **전달되는 곳** | `INTAKE_WEBHOOK_URL`(슬랙 워크플로) 한 곳. 실패하면 `RESEND_API_KEY`+`INTAKE_EMAIL_TO` 로 2차 시도 — **지금 그 둘이 없어서 2차 시도가 없습니다** |
| **둘 다 실패하면** | **503** · 손님 화면에 "지금은 접수되지 않았습니다" + 적은 내용 복사 단추 |
| **가는 내용** | 성함 · 연락처 · 이메일 · 업종 · 지역 · 분류 · 서비스 · 예산 · 요청 조건 · **신청 서비스 n개(항목별 답 포함)** · 적어 주신 내용 · 업체에 물어봐 달라고 하신 것 — 슬랙 채널에 **평문**입니다 |
| **받는 사람** | 그 슬랙 워크플로가 꽂힌 채널의 사람들. 방침의 수탁자에 `Slack Technologies, LLC`(미국)가 적혀 있습니다 (제26조 · 제28조의8) |
| **유일한 사본** | **슬랙 메시지입니다.** 다른 어디에도 없습니다 |
| 접수번호 | **발급하지 않습니다.** 저장이 안 되는데 번호를 주면 그 번호로 물어봐도 아무것도 없습니다 (절대 규칙 5) |

## DB · 환경변수를 켠 뒤

```
  → ① request 표에 한 줄 (성함 · 연락처 · 동의 시각 · 멱등 열쇠)
  → ② 항목은 save_request_items() 로 **한 트랜잭션**
  → ③ 접수번호 SW-····-···· 발급 → 손님 화면 + 슬랙 글 맨 위
  → ④ 슬랙으로 그대로 전달
  → ⑤ (선택) 손님에게 접수 완료 안내 메일
```

- `/admin` → **접수 · 배정** 목록에서 봅니다.
  ⚠️ **목록에는 성함 · 연락처가 없습니다** (`api/me.js` 의 `PICK.staff`) —
  "연락처 보기" 를 누르면 **그 한 건만** 오고 **열람 이력이 남습니다**
  (개인정보보호법 제29조).
- 제3자 제공 동의(제17조 제2항)는 접수 때 **비워 둡니다** — 업체가
  정해지고 상호를 알린 뒤 다시 받습니다.

# Q2. 슬랙 실패 · 중복 접수 때 **신청이 사라질 수 있는가**

## 사라지는 길 — **지금은 하나 있습니다**

| 경우 | 지금 | DB 켠 뒤 |
|---|---|---|
| 슬랙이 **거절**(4xx/5xx) | 503 → 손님이 다시 누를 수 있음. **안 누르고 떠나면 사라집니다** | `request` 에 **이미 저장돼 있습니다** |
| 슬랙이 **대답을 안 함** | `deliver()` 에 **시간 제한이 없습니다** → Vercel 함수 제한에 걸립니다. 화면은 20초에 끊고 실패 처리 | 같음 · 저장은 됨 |
| 손님이 **두 번 누름** | 멱등 열쇠가 같아도 **조회가 안 걸려** 슬랙에 **2건** (아래) | 둘째 insert 가 unique 로 막힘 → 중복 없음 |
| 손님이 **창을 닫음** | 사라집니다 | 저장돼 있습니다 |

⚠️⚠️ **그래서 지금 유실 위험의 본질은 "슬랙이 유일한 사본" 이라는 것**
입니다. 채널 글이 묻히거나 보존 기간이 지나면 그 신청은 없습니다.

## ⚠️ 중복 · 멱등 검사가 **하이픈 번호에서 통째로 무효**입니다

```
저장되는 값   request.tel = "010-1234-5678"   (적어 주신 그대로)
찾는 질의     ?tel=eq.01012345678             (숫자만 남긴 값)
            → 한 줄도 안 걸립니다
```

`api/quote.js` 가 **첫째 자물쇠(조회)** 를 숫자만으로 묻는데 표에는
하이픈이 든 값이 들어갑니다. 그 조회가 0건이면 **그 안에서 하는 멱등
비교와 스팸 판정도 같이 안 돕니다.**

- **유실은 없습니다** — `0009` 의 부분 unique 인덱스(`request_idem_once`)가
  **둘째 자물쇠**로 둘째 줄을 막습니다.
- 대신 ① **슬랙에 2건**이 가고 ② 다시 누른 손님은 **접수번호를 못
  받습니다**(insert 가 막혀 번호가 안 나갑니다).
- 1시간 5건 **스팸 판정도 같은 까닭으로 안 걸립니다.**

⚠️ 이것은 이미 `CLAUDE.md` 에 적어 둔 것이고 **일부러 안 고쳤습니다** —
고치는 길이 둘이고(두 꼴을 `or` 로 묻기 · 시간만으로 가져와 JS 에서
견주기) **둘 다 "무엇을 중복으로 볼지" 를 바꿉니다.** 대표님 판단이
필요한 자리입니다. (업체 입점 쪽은 2026-10-25 에 **시간만으로 가져와
숫자만 남겨 견주는** 쪽으로 만들었습니다.)

## ⚠️⚠️ DB 를 켜면 생기는 **비대칭** — 운영 지침이 필요합니다

저장이 **전달보다 먼저**입니다. 그래서 —

```
저장 성공 → 슬랙 실패 → 손님은 "접수되지 않았습니다" 를 봅니다
                      → 그런데 DB 에는 들어가 있습니다
```

⚠️ **운영자는 슬랙이 아니라 `/admin` 접수 목록을 기준으로 보셔야
합니다.** 슬랙만 보시면 이 건을 영영 못 봅니다.

# Q3. 제휴업체가 등록되면 **고객정보를 안전하게 넘기고 상담 결과를 추적할 수 있는가**

## 넘기는 쪽 — ✅ 됩니다 (설정 후)

| 자물쇠 | 무엇 |
|---|---|
| **배정 = 제3자 제공** | `agree3rd` 가 `true` 가 아니면 DB 가 배정을 **거절**합니다. 동의 **시각**이 `assignment.agree3rd_at` · `request.agree3rd_at` 양쪽에 남습니다 (제17조 제2항) |
| **배정 가능 플래그** | `provider.assignable` 이 **기본 꺼짐**입니다. 구두 합의 단계의 업체로는 **넘어가지 않습니다** — 트리거가 막습니다 |
| **업체가 보는 범위** | `api/me.js` 의 `PICK.provider` — 성함 · 연락처 · 요청 내용. ⚠️ **배정된 항목만** 옵니다 (RLS 의 `item_provider`) — 같은 신청에 담긴 다른 서비스는 안 보입니다 |
| **직원 목록** | 성함 · 연락처 **없음**. 한 건을 열 때만 + 열람 이력 |
| **업체 담당자** | `provider_contact` **별도 표** — 고객 정책이 **아예 없습니다**. `provider` 에 넣으면 `grant select on provider to authenticated` 가 표째라 로그인한 손님 전부가 직통 번호를 읽습니다 |

## 추적하는 쪽 — ✅ 상태는 됩니다 / ⚠️ 통화 메모는 칸이 없습니다

- 상태 **열셋**(접수 → 확인 → 배정 → 수락 → 상담 → 견적 → 협의 →
  계약 → 완료 → 정산 대기 → 정산 완료 · 취소 · 보류)이 **길 표
  서른**으로만 움직이고, **모든 변경이 `audit_log` 에 같은 트랜잭션으로**
  남습니다 (누가 · 언제 · 왜). `/admin` 에서 건별 이력을 봅니다.
- 담당자(`request.owner_id`) · "내 건" 칩이 있어 **같은 건에 두 사람이
  전화하는 일**을 막습니다.
- 견적은 `quote` 표에 금액 · 포함 범위 · 기간 · A/S 로 남고 고객이
  고릅니다. ⚠️ **금액순으로 줄 세우지 않습니다** (포함 범위가 달라
  견줄 수 없고, 줄 세우면 그 순서가 곧 추천입니다).

⚠️ **빠진 것 — `request` 에 메모 칸이 없습니다.** "전화했는데 다음 주에
다시 연락 달라고 하셨다" 를 **상태를 바꾸지 않고** 적어 둘 자리가
없습니다. 지금은 상태를 옮길 때 `why` 로만 남습니다. (영업 작업대의
메모는 **업체 영업용**이고 고객 건과 다른 데이터입니다.)

# Q5. 마이그레이션 · 환경변수를 켠 **직후에 반드시 해야 하는 운영 테스트**

> 자세한 순서는 `docs/GO-LIVE.md` 입니다. 여기는 **테스트만** 모았습니다.

## A. 설정이 실제로 들어갔는가 (2분)

| 무엇 | 어디서 | 기대값 |
|---|---|---|
| 저장 · 로그인 · 판 번호 · 버킷 | **`/admin` 1번 칸** | 저장 ✅ · 로그인 ✅ · "마이그레이션 남은 것 0" · **버킷 비공개 ✅** |

## B. 손님 쪽 한 바퀴 (10분) — ⚠️ **진짜 연락처로**

1. `/quote` 에서 서비스 **둘 이상** 골라 한 건 제출
2. 화면에 **접수번호 `SW-····-····`** 가 뜨는가
3. **슬랙에 도착**했고 글 맨 위에 **같은 번호**가 있는가
4. `/admin` 접수 목록에 **그 건**이 보이는가 (번호로 확인)
5. **"연락처 보기"** 를 누르면 연락처가 오고 **이력에 열람 기록**이 남는가
6. 사진 칸이 뜨는가 → **한 장 올려 보고** `/admin` 에서 보이는가
7. 접수 완료 안내 메일을 켜셨으면 **받은 메일에 번호가 있는가**
   (⚠️ 광고 문구가 섞여 있지 않은가)
8. **같은 폼을 두 번** 보내 보기 → 둘째에 "이미 접수되었습니다"
   ⚠️ 하이픈 없는 번호(`01012345678`)로도 한 번 해 보세요 — 그때만
   첫째 자물쇠가 걸립니다

## C. 권한이 실제로 막히는가 (10분) — ⚠️ **제일 중요합니다**

# Q6. 첫 고객 1명이 **신청 → 상담 → 계약 → 수수료**까지 막히는 데가 있는가

```
① 신청 접수            ✅ 됩니다 (DB 켠 뒤 번호까지)
② 직원이 정보 확인      ✅ 됩니다
③ 업체 배정 (제17조)    ✅ 됩니다 — ⚠️ assignable + 동의 체크 필요
④ 업체가 수락          ⛔ **막힙니다** ← 업체 계정이 그 업체에 이어져 있어야
⑤ 상담 시작            ⛔ 같은 까닭
⑥ 견적 제출            ⛔ 같은 까닭
⑦ 계약 협의            ⛔ 같은 까닭 (업체 · 고객만)
⑧ 계약 완료            ✅ 직원 · 관리자도 됩니다 — 그런데 ⑦에 도달 못 함
⑨ 서비스 완료          ✅
⑩ 수수료 확정 · 입금    ✅ 관리자만
```

## ⛔ 막히는 자리는 **하나**입니다 — ④~⑦

재 보니 **네 전이가 업체(provider) 전용**입니다 (`js/data/deal.js`) —

```
assigned → accepted   provider
accepted → consult    provider
consult  → quoted     provider
quoted   → nego       provider / customer     ← 직원도 관리자도 없습니다
```

**업체가 로그인하지 않으면 건이 `배정` 에서 영원히 멈춥니다.** 직원이
전화로 다 듣고 와도 대신 넘길 수 없습니다.

그래서 **업체 계정을 업체에 잇는 일이 "선택" 이 아니라 필수 단계**
입니다 (§새로 찾은 것 ②).

## 그 밖에 막히지는 않지만 불편한 것

- 상담 메모 칸이 없어, 통화 내용을 남기려면 **상태를 옮기면서** 적어야
  합니다 (Q3).
- 업체가 "전화로만" 하겠다고 하면 ④~⑦ 이 안 됩니다 — 그러면 그 업체는
  **배정 대상으로 두기 어렵습니다.**
