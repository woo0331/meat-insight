## 0. 지금 어디까지 됐는지 **먼저 보세요**

⚠️⚠️ **이 문서를 믿지 마세요.** 이 저장소에서 "켰습니다" 가 몇 주
동안 거짓이었던 적이 있습니다. **지금 되는지는 화면이 말합니다** —

```
storeway.co.kr/admin  을 열고 **1번 칸**을 봅니다
```

| 1번 칸이 말하는 것 | 뜻 |
|---|---|
| `store` | 접수 저장 · 접수번호 (`SUPABASE_URL` + `SUPABASE_SERVICE_KEY`) |
| `auth` | 로그인 · 마이페이지 (`SUPABASE_URL` + `SUPABASE_ANON_KEY`) |

⚠️ **둘을 갈라서 봅니다.** service key 만 넣고 공개 키를 빠뜨리면
**접수번호는 나오는데 로그인만 조용히 안 됩니다** — 화면이 구간째
안 그려서 아무 에러도 안 납니다.

⚠️ `/admin` 은 **2번 칸**이 "영업 시작 전에 남은 것" 을 **세어서**
말합니다. 채우시면 저절로 사라집니다.

## 2. `0008_quote.sql` 돌리기 (DB · 10분)

지금 `0001`~`0007` 까지 돌아가 있고 **0008 만 남았습니다.**

1. Supabase 대시보드 → **SQL Editor**
2. `db/migrations/0008_quote.sql` 을 **통째로** 붙여 넣고 **Run**
   - ⚠️⚠️ **중간을 잘라서 돌리지 마세요.** 한 파일이 한 트랜잭션입니다
3. 이어서 `db/verify.sql` 을 **통째로** 붙여 넣고 **Run**

**열세 줄이 전부 ✅ 라야 합니다.** 기대값은 —

```
판 번호 8 · 표 12 · RLS 안 켜진 표 0 · 상태 13(hold 포함) · 역할 4 ·
길 70 · 문(함수) 19 · 가입 트리거 1 · auth.uid() 1 ·
돈 칸 쓰기 권한 0 · 감사 기록 수정·삭제 정책 0 · anon 권한 0 ·
가입 시 역할 customer 1
```

⚠️ **0008 을 안 돌리셨으면 판 7 · 표 11 · 함수 16 으로 나옵니다** —
그건 DB 가 망가진 게 아니라 **0008 을 돌리시면 되는 것**입니다.
⚠️ 다른 줄이 ❌ 면 그때는 무언가 바뀐 것이니 멈추고 알려 주세요.

⚠️⚠️ **큰일 전에는 백업부터.** `db/README.md` §3-2 에 뜨는 법이
있습니다.

## 3. Vercel 환경변수 셋 + **다시 배포** (15분)

Vercel → 프로젝트 → **Settings → Environment Variables**

| 이름 | 어디서 가져오나 | 쓰는 곳 |
|---|---|---|
| `SUPABASE_URL` | Supabase → Settings → API → Project URL | 서버 함수 |
| `SUPABASE_ANON_KEY` | 같은 화면의 **anon public** | 화면 **과** 서버 함수 |
| `SUPABASE_SERVICE_KEY` | 같은 화면의 **service_role** | 서버 함수 **하나**만 |

- ⚠️ **Production 에 체크**가 되어 있는지 보세요.
- ⚠️⚠️ **넣은 뒤 반드시 다시 배포하세요.** 떠 있는 함수에는 값이
  안 들어갑니다. (Deployments → 맨 위 → ⋯ → **Redeploy**)
- ⚠️⚠️ **`SUPABASE_SERVICE_KEY` 는 RLS 를 통째로 지나갑니다.** 한 번
  새면 손님 연락처와 계약금액 전부가 새는 것과 같습니다 — 어디에도
  붙여 넣지 마시고, 화면에 보여 주는 주소를 만들지 마세요.
- ⚠️ **공개 키(anon)가 서버 함수에도 필요합니다.** 빠뜨리면 로그인만
  조용히 안 됩니다 (위 0번).

**다시 배포한 뒤 `/admin` 1번 칸에서 `store` · `auth` 둘 다 켜졌는지
확인하세요.**

## 4. Supabase **Redirect URLs** 넣기 (5분)

로그인은 **메일로 오는 링크**입니다 (비밀번호가 없습니다). 돌아올
주소가 등록돼 있어야 링크가 제자리로 옵니다.

Supabase → **Authentication → URL Configuration → Redirect URLs** 에 —

```
https://storeway.co.kr/my
https://storeway.co.kr/admin
```

⚠️ 안 넣으면 링크를 눌렀을 때 **기본 주소**로 가 버립니다.
⚠️ Site URL 은 `https://storeway.co.kr` 입니다.

## 5. 첫 관리자 만들기 (5분)

1. `storeway.co.kr/my` 에서 **사장님 메일로 로그인**합니다
   (메일로 온 링크를 누르면 끝입니다)
2. Supabase → **Authentication → Users** 에서 그 계정의 **User UID** 복사
3. SQL Editor 에서 —

```sql
update account set role = 'admin' where id = '<복사한 UID>';
```

4. `storeway.co.kr/admin` 을 다시 열면 접수 · 배정 칸이 보입니다

⚠️⚠️ **화면에 "관리자 되기" 단추를 만들지 않았습니다.** 그런 단추가
있으면 그게 가장 큰 구멍입니다 — 역할 올리기는 **SQL 로만** 합니다.
⚠️ 가입할 때 역할을 보내도 무시됩니다 (트리거가 `customer` 로 박습니다).

## 7. ⚠️⚠️ **같은 날 같이 움직이는 셋**

이 저장소에서 **세 번** 어긋났던 자리입니다.

```
① Vercel 환경변수      ②  js/data/site.js 의 준비 상태값
                       ③  js/data/legal-privacy.js 의 trustees
```

새 회사(Supabase · Slack · Resend 등)가 손님의 성함 · 연락처를 받게
되는 순간, **개인정보 처리위탁**이 늘어납니다 (제26조). 방침에
**수탁자 이름 · 위탁 업무 · 보유기간**을 적어야 하고, 미국 법인이면
**국가**까지 적습니다 (제28조의8).

⚠️ 반대로 **안 쓰는 회사를 적어 두는 것도 사실과 다른 방침**입니다.

> Supabase 는 서울(ap-northeast-2)이라 국외 이전은 아닙니다. 방침에
> 이미 들어가 있습니다 — 바꾸실 때만 같이 보세요.
