## 0. 지금 어디까지 됐는지 **먼저 보세요**

⚠️⚠️ **이 문서를 믿지 마세요.** 이 저장소에서 "켰습니다" 가 몇 주
동안 거짓이었던 적이 있습니다. **지금 되는지는 화면이 말합니다** —

```
storeway.co.kr/admin  을 열고 **1번 칸**을 봅니다
```

| 1번 칸이 말하는 것 | 뜻 | 필요한 것 |
|---|---|---|
| `webhook` | 접수가 슬랙 · 메일로 가는가 | `INTAKE_WEBHOOK_URL` |
| `store` | 접수 저장 · 접수번호가 나오는가 | `SUPABASE_URL` + `SUPABASE_SERVICE_KEY` |
| `auth` | 로그인 · 마이페이지가 그려지는가 | `SUPABASE_URL` + `SUPABASE_ANON_KEY` |
| **판 번호** | **마이그레이션을 다 돌렸는가** | 아래 1번 |
| **버킷** | **비공개인가 · 상한이 걸렸는가** | 아래 2번 |

⚠️ **갈라서 봅니다.** service key 만 넣고 공개 키를 빠뜨리면
**접수번호는 나오는데 로그인만 조용히 안 됩니다** — 화면이 구간째
안 그려서 아무 에러도 안 납니다.

⚠️⚠️ **2026-10-21 — 1번 칸이 DB 를 직접 읽습니다.** 전에는 **키가
들어갔는지**만 보고 "다 설정되어 있습니다" 라고 했습니다. 키를 다
넣어도 `0008`~`0011` 을 안 돌리셨으면 **견적도 · 항목별 배정도 ·
회원 저장도 · 사진도 조용히 안 되는데** 화면은 아무 말도 안 했고,
그걸 아는 길이 SQL Editor 를 열어 `db/verify.sql` 을 붙여 넣는 것
하나였습니다. 이제 거기서 —

```
마이그레이션이 3개 남았습니다 — 지금 판 8 · 저장소는 판 11
  db/migrations/0009_request_item.sql   남음
  db/migrations/0010_user_state.sql     남음
  db/migrations/0011_request_photo.sql  남음
```

처럼 **남은 파일 이름까지** 적어 줍니다. 버킷도 **실제로 비공개인지 ·
8MB 가 걸려 있는지 · 형식이 넷인지**를 보고 말합니다.

- ⚠️ **못 읽었을 때는 "안 돌렸습니다" 라고 하지 않습니다** — "읽지
  못했습니다" 입니다. 못 읽은 것을 안 됐다고 적으면 멀쩡한 DB 를
  고치러 가시게 됩니다.
- ⚠️ **기대값을 손으로 적지 않습니다.** 빌드가 `db/migrations` 를 읽어
  적고(`api/_migrations.js`) 서버가 셉니다 — 마이그레이션을 늘리면
  저절로 따라옵니다.
- ⚠️ 판 번호 · 파일 이름은 공개 저장소에 그대로 있는 값이라 돌려줘도
  새는 것이 없습니다. **버킷 이름과 설정값은 안 돌려줍니다.**

⚠️ `/admin` **2번 칸**은 "영업 시작 전에 남은 것" 을 **세어서**
말합니다 (사업자 정보 빈 칸 · 지원사업 링크). 채우시면 저절로
사라집니다 — 손으로 지우는 줄이 아닙니다.

## 1. DB — `0008` ~ `0011` 돌리기 (20분)

지금 **`0001`~`0007` 까지** 돌아가 있고 **넷이 남았습니다.**

| 파일 | 무엇 |
|---|---|
| `0008_quote.sql` | 업체가 견적을 내고 고객이 고르는 표 |
| `0009_request_item.sql` | **신청 하나에 서비스 여러 개** + 항목별 배정 |
| `0010_user_state.sql` | 로그인한 계정에 남는 임시저장 · 체크 |
| `0011_request_photo.sql` | 신청에 붙는 **사진 · 서류** |

1. ⚠️⚠️ **먼저 백업부터.** `db/README.md` §3-2 에 뜨는 법이 있습니다.
2. Supabase 대시보드 → **SQL Editor**
3. `db/migrations/0008_quote.sql` 을 **통째로** 붙여 넣고 **Run**
   - ⚠️⚠️ **중간을 잘라서 돌리지 마세요.** 한 파일이 한 트랜잭션입니다
4. 같은 방법으로 `0009` → `0010` → `0011` 을 **번호 차례대로**
5. 마지막에 `db/verify.sql` 을 **통째로** 붙여 넣고 **Run**

**열세 줄이 전부 ✅ 라야 합니다.** 기대값은 —

```
판 번호 11 · 표 15 · RLS 안 켜진 표 0 · 상태 13(hold 포함) · 역할 4 ·
길 70 · 문(함수) 28 · 가입 트리거 1 · auth.uid() 1 ·
돈 칸 쓰기 권한 0 · 감사 기록 수정·삭제 정책 0 · anon 권한 0 ·
가입 시 역할 customer 1
```

⚠️ **덜 돌리셨으면 판 · 표 · 함수 셋만** 어긋납니다 — 그건 DB 가
망가진 게 아니라 **남은 파일을 돌리시면 되는 것**입니다.
⚠️ 키를 먼저 넣으셨다면 **`/admin` 1번 칸이 남은 파일 이름을 그대로
적어 줍니다** — `verify.sql` 을 안 돌려 보셔도 무엇이 남았는지는
거기서 보입니다 (위 0번).
⚠️⚠️ **다른 줄이 ❌ 면 멈추고 알려 주세요** — 무언가 바뀐 것입니다.
⚠️ 번호를 **다시 쓰지 않습니다.** 돌린 파일을 고치지 말고 다음
번호로 새로 만듭니다.

## 2. Storage **비공개 버킷** 만들기 (10분 · 사진 첨부용)

`0011` 만으로는 **사진이 안 올라갑니다.** 받아 둘 자리가 따로
필요합니다.

1. Supabase → **Storage → New bucket**
2. 이름은 짧은 영문으로 (예: `intake`) — 그 이름을 **그대로**
   `INTAKE_BUCKET` 에 넣습니다 (아래 3번)
3. ⚠️⚠️ **Public 을 끄세요.** 공개 버킷이면 **경로를 아는 누구나**
   사장님들이 올린 사진을 봅니다. 보는 길은
   `/api/upload?p=<사진 id>` 하나이고 누가 볼 수 있는지는 RLS 가
   정합니다 (업체는 **배정된 건만**).
4. 그 버킷 설정에 **같은 상한을 같이** 거세요 —

```
크기 상한   8 MB
허용 형식   image/jpeg · image/png · image/webp · application/pdf
```

⚠️⚠️ **서명된 올리기 주소는 그 자체로 크기와 형식을 막지 않습니다.**
서버(`api/upload.js`)와 DB(`0011`)가 각각 막고 있지만, 그 둘이 보는
것은 **"적어 보낸 값"** 입니다 — 실제로 막는 마지막 자물쇠가 버킷
설정입니다. 셋 다 같은 값이라야 합니다.

⚠️ `INTAKE_BUCKET` 이 없으면 사진 칸이 **아예 안 그려집니다** (단추도
안내도 "준비 중" 도 없습니다). 그게 맞습니다 — 못 올리는데 올리는
척하는 화면을 만들지 않습니다.

⚠️⚠️ **버킷을 만드신 뒤 `/admin` 1번 칸을 한 번 보세요.** 2026-10-21
부터 거기가 버킷을 **실제로 읽어** 공개인지 · 상한이 걸렸는지 ·
형식이 넷인지를 말합니다 — 이름만 환경변수에 넣고 Public 을 못 끄신
경우가 제일 위험한데, 화면으로는 표가 전혀 안 나는 자리였습니다.

## 3. Vercel 환경변수 + **다시 배포** (15분)

Vercel → 프로젝트 → **Settings → Environment Variables**

### 꼭 있어야 하는 것

| 이름 | 어디서 가져오나 | 없으면 |
|---|---|---|
| `ADMIN_PASSWORD` | 사장님이 정하십니다 (길고 추측 안 되는 것) | `/admin` 이 **503** 으로 안 열립니다 |
| `INTAKE_WEBHOOK_URL` | 슬랙 워크플로 주소 | 접수가 **503** 으로 거절됩니다 |
| `SUPABASE_URL` | Supabase → Settings → API → **Project URL** | 저장 · 로그인 둘 다 안 됩니다 |
| `SUPABASE_ANON_KEY` | 같은 화면의 **anon public** | **로그인만** 조용히 안 됩니다 |
| `SUPABASE_SERVICE_KEY` | 같은 화면의 **service_role** | 접수가 저장이 안 되고 **번호가 안 나옵니다** |
| `INTAKE_BUCKET` | 2번에서 만든 버킷 이름 | 사진 칸이 **안 나옵니다** |

### 안 넣어도 되는 것 (넣으면 그쪽으로 더 갑니다)

| 이름 | 무엇 |
|---|---|
| `RESEND_API_KEY` + `INTAKE_EMAIL_TO` | 접수를 **메일로도** 받기 |
| `INTAKE_EMAIL_FROM` | 보내는 주소 (기본값 `onboarding@resend.dev`) |
| `DEAL_WEBHOOK_URL` | 상태 변경 알림을 **접수와 다른 채널**로 |
| `QUOTE_WEBHOOK_URL` · `PARTNER_WEBHOOK_URL` · `SOS_WEBHOOK_URL` | 종류마다 다른 채널로 (`_EMAIL_TO` 도 같은 꼴) |

### ⚠️ 넣을 때 틀리기 쉬운 것 넷

- ⚠️⚠️ **Production 에 체크**가 되어 있는지 보세요. Preview 에만
  들어가 있으면 운영 주소에서는 **없는 것**입니다.
- ⚠️⚠️ **넣은 뒤 반드시 다시 배포하세요.** 이미 떠 있는 함수에는 값이
  안 들어갑니다 (Deployments → 맨 위 → ⋯ → **Redeploy**).
- ⚠️ **앞뒤 공백 · 줄바꿈이 섞이지 않게** 붙여 넣으세요. 공백만 있는
  값은 코드가 **없는 것**으로 봅니다 — "넣었는데 왜 안 되지" 가
  거기서 납니다.
- ⚠️⚠️ **`SUPABASE_SERVICE_KEY` 는 RLS 를 통째로 지나갑니다.** 한 번
  새면 손님 연락처와 계약금액 전부가 새는 것과 같습니다 — 메신저 ·
  메모 · 저장소 어디에도 붙여 넣지 마시고, 그 값을 돌려주는 주소를
  만들지 마세요. (`/api/admin-health` 는 **있는지 없는지**만 말하고
  값도 길이도 안 돌려줍니다.)

**다시 배포한 뒤 `/admin` 1번 칸에서 `webhook` · `store` · `auth` 가
전부 켜졌는지 확인하세요.**

## 4. Supabase **Redirect URLs** 넣기 (5분)

로그인은 **메일로 오는 링크**입니다 (비밀번호가 없습니다). 돌아올
주소가 등록돼 있어야 링크가 제자리로 옵니다.

Supabase → **Authentication → URL Configuration**

```
Site URL        https://storeway.co.kr
Redirect URLs   https://storeway.co.kr/my
                https://storeway.co.kr/admin
```

⚠️ 안 넣으면 링크를 눌렀을 때 **기본 주소**로 가 버립니다.

## 5. 첫 관리자 만들기 (5분)

1. `storeway.co.kr/my` 에서 **사장님 메일로 로그인**합니다
   (메일로 온 링크를 누르면 끝입니다)
2. Supabase → **Authentication → Users** 에서 그 계정의 **User UID** 복사
3. SQL Editor 에서 —

```sql
update account set role = 'admin' where id = '<복사한 UID>';
```

4. `storeway.co.kr/admin` 을 다시 열면 접수 · 배정 칸이 보입니다

⚠️⚠️ **화면에 "관리자 되기" 단추를 만들지 않았습니다.** 그런 단추가
있으면 그게 가장 큰 구멍입니다 — 역할 올리기는 **SQL 로만** 합니다.
⚠️ 가입할 때 역할을 보내도 무시됩니다 (트리거가 `customer` 로 박습니다).
⚠️ 직원은 `'staff'` 입니다 — 계약을 따는 사람과 **수수료를 확정하는
사람**을 가르려고 역할이 넷입니다.

**국가**까지 적습니다 (제28조의8).

> 이미 들어가 있습니다 — 바꾸실 때만 같이 보세요.
