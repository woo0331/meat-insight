# 사진을 넣는 법 · 자리별 규격

> **2026-10-10 "STOREWAY 이미지 개선 작업지시서"** 에 대한 답입니다.
> 지시서 §4 — *"외부 이미지 검색 결과를 무단으로 다운로드해 상업적으로
> 사용하지 않는다. 사용 권한이 확인된 이미지 또는 스토어웨이 전용으로
> 생성한 이미지를 사용한다."*

---

## 0. 먼저 — 제가 **사진 자체는 못 만듭니다**

| 길 | 왜 안 되나 |
|---|---|
| 검색해서 받기 | 지시서 §4 가 **직접 금지**합니다. 상업적 이용이 확인 안 된 사진은 그 순간 분쟁거리입니다 |
| AI 로 만들기 | 이 작업 환경에 그림을 만드는 도구가 없습니다. 있더라도 §54(의미 없는 AI 이미지 남발 금지)와 §2(과도하게 인위적인 AI 느낌 회피)에 걸립니다 |
| 직접 찍기 | 제가 카메라가 없습니다 |

**그래서 사진 네 장은 사장님이 주셔야 합니다** — 직접 찍은 것 · 상업적
이용이 되는 유료 스톡 · 저희 전용으로 만든 것 셋 중 하나입니다.
⚠️ 알아볼 수 있는 얼굴이 있으면 초상권 동의를 따로 받으세요.

**제가 한 것은 그 사진이 들어갈 자리를 전부 준비해 둔 것**입니다 —
파일만 넣고 명령 두 줄을 돌리면 화면 코드는 **한 줄도 안 고칩니다.**

---

## 1. 넣는 법 (명령 두 줄)

```bash
# ① 원본을 자리 이름 그대로 img/raw/ 에 넣습니다 (크기 · 용량 안 맞춰도 됩니다)
#    img/raw/svc-equip.jpg

node tools/fit-photos.js --write   # 규격에 맞춰 jpg · webp · 폰용까지 네 벌
node tools/check-photos.js         # 규격 · alt 확인
node build-pages.js                # 화면 161개에 반영
```

⚠️ `--write` 뒤에 **`alt` 를 사람이 적어야 합니다** (`js/data/photos.js`).
비어 있으면 빌드가 멈춥니다 — 눈이 불편한 분과 검색엔진이 읽는 글입니다.

## 3. ⚠️⚠️ 먼저 정해 주셔야 하는 것 셋

### ① 메인 03 서비스 카드 — 지금은 **사진 자리가 76~92px** 입니다

재 보았습니다 (1440 · 1024 · 768 · 390px).

```
svc-*  76px (1440) · 76px (1024) · 76px (768) · 62px (390)
```

2026-10-09 지시서 §3 이 **"핵심 서비스 카테고리에는 컬러형 아이콘을
적용"** 이라고 적어서, 그 자리는 지금 **컬러 아이콘 원판**입니다.
640×420 짜리 주방 사진을 넣어도 **동전만 한 원 안에** 들어갑니다 —
무엇인지 안 보이고 받는 용량만 늘어납니다.

| 고르실 수 있는 것 | 결과 |
|---|---|
| **(가) 그대로 둡니다** | 아이콘 유지. 사진은 히어로 · 연결 구간 · 단계 카드로 (지금 권하는 쪽) |
| (나) 카드에 **사진 띠**를 답니다 | 카드 위에 16:7 띠가 생기고 아이콘은 그 아래로. 메인이 길어지고, 10-09 지시서의 아이콘 결정을 뒤집는 것입니다 |

⚠️ 이 저장소는 같은 자리를 **하루 만에 두 번 뒤집은 적**이 있습니다
(상품 여덟 ↔ 분류 여덟). 그래서 **사장님이 정해 주시면** 하겠습니다.

### ② `feat-*` 세 자리는 **지금 화면에 안 나옵니다**

`feat-franchise` · `feat-store` · `feat-interior` 는 `MainFeature()` 가
쓰는데, 그 구간이 2026-10-08 개편 때 메인에서 내려왔습니다. 함수는
그대로 있어서 되살리면 바로 나옵니다 — 다만 **지금 사진을 사시면 돈만
나갑니다.** 되살릴지 먼저 정해 주세요.

---

### ③ **상세 페이지에는 사진 자리가 아예 없습니다**

지시서 §3 이 *"관련 서비스 상세페이지의 대표 이미지"* 를 적었는데,
`photoBox()` 를 부르는 파일이 **`js/pages/home.js` 하나**입니다 —
`/c/:cat` · `/providers/:cat` · `/stores` · `/franchise` 같은 상세 ·
목록 화면에는 사진이 들어갈 자리가 **만들어져 있지 않습니다.**

| 고르실 수 있는 것 | 결과 |
|---|---|
| **(가) 그대로 둡니다** | 상세 화면은 지금처럼 글과 카드로. 사진 네 장을 메인에 집중 |
| (나) 분야마다 **머리 사진**을 답니다 | 자리 26개(분류 수)가 새로 생깁니다 — 사진도 26장이 필요하고, 한 장이라도 비면 그 분야만 허전해 보입니다 |

⚠️ (나)로 가시면 **분야 하나에 한 장씩**이라 스물여섯 장입니다.
네 장으로는 채울 수 없고, 빈 자리는 글 짜임새로 떨어지므로 분야마다
생김새가 달라집니다. **먼저 네 장을 메인에 넣고 보시는 쪽**을 권합니다.

## 4. 전후 비교 · 속도 검증 (지시서 §4)

사진 **내용**은 안 바뀌었습니다(같은 두 장입니다). 바뀐 것은 **어떻게
내보내는가**이고, 재 본 값은 이렇습니다.

### 받는 양

| | 변경 전 | 변경 후 |
|---|---|---|
| 첫 화면 그림 | `hero-start.jpg` 297KB + `hero-close.jpg` 295KB = **592KB** | `-sm.webp` 77KB × 2 = **155KB** |
| 화면 전체 | 2,048KB | **1,615KB** |

**그림만 −74%, 화면 전체 −21%** 입니다. 폰에서 쓰는 데이터가 그만큼
줄고, 자리 스물세 곳이 다 차면 그 비율 그대로 커집니다.

### 화면 품질

같은 자리 크기(605×269)로 세 판을 나란히 놓고 찍어서 봤습니다 —
**눈으로 구분이 안 됩니다.** WebP 예산을 처음에 넉넉히 주었더니
297KB → 239KB(19%)밖에 안 줄어서, 조여서 다시 재고 **눈으로 확인한
뒤** 지금 값으로 정했습니다.

### ⚠️⚠️ 그런데 **LCP 는 거의 안 바뀌었습니다** — 사진이 병목이 아닙니다

폰 390px · 1.6Mbps · 지연 150ms 에서 세 번씩 재 가운데값입니다.

```
변경 전  LCP 5,824ms
변경 후  LCP 5,808ms      ← 16ms 차이
```

까닭을 찾아보니 **LCP 가 사진이 아니라 글(h1)** 이고, 그 글이 뜨는
시점을 **스크립트가 잡고 있었습니다** —

```
스크립트 43개 · 1,169KB · 마지막 파일이 7,566ms 에 끝남
CSS 289KB
```

즉 **첫 화면이 뜨는 속도는 사진이 아니라 자바스크립트가 정합니다.**
사진을 더 줄여도 이 숫자는 안 움직입니다.

⚠️ 이건 이번 지시서 범위 밖이라 **건드리지 않았습니다.** 손대실
생각이시면 그때 따로 재서 올리겠습니다 — 데이터 파일을 묶거나, 첫
화면에 필요 없는 것을 나중에 받게 하는 쪽입니다. 다만 이 저장소는
`defer` 로 한 번 6.3초 → 2.3초를 줄인 적이 있어서, **구조를 바꾸는
일**이라 따로 보셔야 합니다.

## 5. 사진을 고르실 때 (이 저장소가 겪은 것)

- ⚠️⚠️ **업종이 드러나면 안 됩니다.** 고깃집 사진을 깔면 미용실
  사장님에게 "여긴 내 자리가 아니네" 가 됩니다. 모든 업종의 사장님이
  손님입니다.
- ⚠️⚠️ **폐업 쪽을 처연하게 찍지 마세요.** 불 꺼진 가게 · 고개 숙인
  사람은 안 됩니다. 지금 `hero-close` 는 햇빛이 가득 드는 밝은
  현장이고, 그 선을 지켜 주세요 — 폐업은 실패가 아니라 정리입니다.
- ⚠️ **사진 안에 글자 · 상호 · 로고가 보이면 안 됩니다.**
- ⚠️ **가로로 넓은 쪽(2:1 안팎)이 낫습니다.** 세로로 길면 넓은 화면에서
  천장과 바닥만 남습니다.
- ⚠️ 히어로는 **가운데에 글이 앉습니다** — 주인공을 가운데 두지 마세요.
- ⚠️ 네 장의 **색감과 밝기를 맞춰** 주세요 (지시서 §2). 한 장만 차갑거나
  어두우면 한 벌로 안 읽힙니다.

## 6. 사진이 없을 때 화면이 하는 일

**빈 액자를 깔지 않습니다.** `hasPhoto()` 가 거짓이면 그 구간은
**글이 주인공인 짜임새**로 갑니다 — "이미지 준비 중" 같은 자리표시자를
찍지 않습니다 (절대 규칙 2). 그래서 지금 사진이 두 장뿐이어도 화면이
미완성으로 보이지 않습니다.
