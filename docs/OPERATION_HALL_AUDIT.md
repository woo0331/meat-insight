## 2. ⚠️⚠️ §1 문제 5 가 **지시서보다 나쁩니다** — 복수 선택이 **없습니다**

지시서는 *"화면에 선택 기능이 보이더라도 … 실제 연결되어 있는지
검증해야 한다"* 로 적었는데, 재 보니 **그 화면에 선택 기능 자체가
없습니다.**

```
`[data-pick]` 체크칸        0개
`input[type=checkbox]`      6개  ← 전부 **패키지 상품** 체크입니다
```

패키지 체크는 **그 카드 하나 안에서만** 되고 카드마다 제 신청 단추가
따로입니다. 그래서 지금 `/operation` 에서는 —

- 마케팅과 세무를 **같이** 고를 수가 없습니다 (카드가 다릅니다).
- 고른 것이 **화면을 떠나면 사라집니다** (주소에만 있습니다).
- 접수에는 **이름이 이어 붙은 한 줄**로 들어옵니다.

창업 준비 전문관은 2026-10-17 에 이것을 고쳤고(`js/pick.js`),
**운영 쪽에는 그 층이 한 줄도 안 붙어 있습니다.**

## 3. §1 문제 1 — 같은 분류가 **최대 열두 번** 반복됩니다

`#view` 안의 `/providers/*` 링크를 주소별로 세었습니다.

| 분류 주소 | 몇 번 |
|---|---|
| `/providers/supply` | **12번** |
| `/providers/repair` | 6번 |
| `/providers/it` | 6번 |
| `/providers/marketing` | 6번 |
| `/providers/clean` | 6번 |

까닭은 **서비스를 내는 영역이 넷**이기 때문입니다 —

```
구간 2  운영 묶음 여섯 (AM_OPSVC)        분류 supply repair it marketing clean admin
구간 3  패키지 (AM_PACKAGES)             상품 → 같은 분류들
구간 4  운영 과제 24 (AM_OPS)            분류 admin staff it supply clean marketing law contract interior
구간 5  업종 열넷 (IndustryGrid)          그 업종의 분류 차례
```

`supply` 가 열두 번인 것은 묶음 **A 식자재**와 **B 소모품 · 포장재**가
둘 다 `supply` 를 가리키고, 운영 과제의 7 · 8 도 거기로 가기
때문입니다. 손님이 "식자재" 를 어디서 골라야 하는지 알 길이 없습니다.

## 4. §1 문제 2 — `/quote` 로 가는 단추가 **셋인데 서로 다릅니다**

| 자리 | 높이 | 글자 | 무엇이 실리나 |
|---|---|---|---|
| y=431 (소개) | 56px | 필요한 것 견적 요청 | **아무것도** (`quoteTo({})`) |
| y=727 (묶음 머리) | 48px | 상담 신청하기 | **아무것도** |
| y=2301 (패키지) | 48px | 6개 묶어서 상담 신청 | 그 패키지의 상품 여섯 |

위 둘은 **빈 신청 화면**을 엽니다. 손님이 묶음 여섯을 다 읽고 내려와
"상담 신청하기" 를 누르면, 방금 본 것이 하나도 안 실린 채 처음부터
적게 됩니다 — 이 저장소가 업체 상세의 `quoteTo({})` 로 한 번 겪은
자리입니다.

## 5. §1 문제 4 — 글씨가 **13 ~ 14.5px** 입니다

## 8. ⚠️⚠️ 새로 만들어야 하는 것 — **둘**입니다

### ① 고르는 단위가 **하위**라야 합니다 (창업 쪽은 분류)

§4-4 와 §5-1 이 직접 적었습니다 —

```
§4-4  '매장 수리' 를 누르면 → 냉장고 · 에어컨 · 전기 · 수도 · 주방기기 · 모르겠어요
§5-1  네이버 플레이스 관리 · 세무 기장 대행 · POS 설치 · 매장 청소
```

전부 **하위 분류** 이름입니다. 그런데 `js/data/svcpick.js` 는
**분류 단위**이고, 그 까닭을 셋으로 적어 두었습니다 (추가 질문이 분류
단위 · 하위 206 은 전화번호부 · `admin` 이 셋을 품음).

⚠️ **창업 쪽 판단은 그대로 맞습니다.** 창업은 "무엇부터 할까" 를 고르는
자리라 분류가 맞고, 운영은 **"지금 이게 고장났다"** 를 고르는 자리라
하위가 맞습니다. 그래서 **둘 다 되게** 넓힙니다 — pick id 를
`repair` (= 모르겠어요) 또는 `repair/aircon-fix` 로 받습니다.

맞물려 고칠 자리 —

| 어디 | 무엇 |
|---|---|
| `amPickOne()` | `cat/sub` 를 읽습니다 (없는 것은 그대로 null) |
| `api/_services.js` | 허용 목록에 **하위 쌍**을 같이 적습니다 (§15) |
| `reqforms` 찾기 | **분류 부분**으로 찾습니다 — 같은 분류의 하위 둘을 고르면 질문이 한 번만 (§7-4) |
| `request_item.service_id` | `text` 라 **표를 안 고칩니다** |

### ② 여덟 대표 서비스 가운데 **둘이 같은 분류**입니다

| §4-2 | 분류 | 겹침 |
|---|---|---|
| 2 세무 · 회계 | `admin` + `tax-agent` | ⚠️ 8번과 같은 분류 |
| 8 보험 · 운영 상담 | `admin` + `insurance` | ⚠️ 2번과 같은 분류 |
| 3 직원 채용 · 노무 | `staff` + `admin/labor-agent` | ⚠️ 분류 둘에 걸칩니다 |

분류 단위로 두면 2번과 8번이 **같은 칸**이 됩니다 — 이 저장소가
`halls.js` 에서 "인허가 · 행정과 세무 · 회계는 둘 다 `admin` 이라
분류색을 쓰면 같은 색" 으로 겪은 자리입니다. 하위 단위로 가면 갈립니다.

## 9. §7-3 이 적은 질문 가운데 **셋이 없습니다**

`AM_REQ_FORMS` 는 열두 분류를 들고 있는데 —

|---|---|

| **`repair`** | ❌ 없음 — §7-3 이 직접 적은 "매장 수리" |
| **`supply`** | ❌ 없음 |
| `fund` | ❌ 없음 (여덟에 안 들어갑니다 — 전체 보기 쪽) |

⚠️⚠️ §7-3 의 **"사진을 첨부하시겠어요?"** 는 그대로 못 만듭니다 —
**받아 둘 저장소가 없습니다.** 업로드 칸을 만들면 손님이 사진을 고르고
눌렀는데 아무 데도 안 가는 꼴이고(절대 규칙 5), §15 의 "첨부파일
검증" 도 검증할 파일이 없습니다. **보내실 수 있는지만 묻고 연락할 때
받겠다고 적습니다.**

## 10. ⚠️ 내려보낼 구간마다 **갈 곳을 재서** 확인할 것
