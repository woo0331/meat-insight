# 1차 플랫폼 운영 시스템 — 기존 시스템 분석

> **2026-10-09 작업지시서 §2 · §13** — *"개발에 앞서 다음 항목을
> 확인한다 · 각 기능을 정상 작동 / 부분 구현 / 화면만 존재 / 미구현으로
> 구분하여 보고한다 · 기존 구현 기능을 중복 개발하지 않는다."*

**개발 전 보고서입니다.** 아래 표를 사장님이 보시고 "이것부터" 를
정해 주시면 그 차례로 붙입니다. ⚠️ 운영 배포는 하지 않았습니다 (§1-8).

---

## 0. 한 줄 요약

```
화면 · 데이터 · 검사  ─ 다 서 있습니다        (화면 161 · 보존 주소 162 · 분류 26 · 하위 206)
접수(견적 요청)       ─ 지금 실제로 돕니다    (슬랙으로 옵니다)
로그인 · DB           ─ 코드는 다 있는데 **Supabase 가 안 서 있습니다**
자동 매칭 · 견적 제출 ─ 아직 없습니다         (이번 지시서의 진짜 새 일)
```

**지금 이 플랫폼에서 막혀 있는 것은 기능이 아니라 DB 한 개입니다.**
회원 · 업체 승인 · 배정 · 견적 제출 · 정산이 전부 그 뒤에 줄을 서
있고, 그 앞단(스키마 · RLS · 서버 API · 검사 452개)은 이미 돌고
있습니다.

|---|---|---|---|

| 6 | 관리자 페이지 | **부분 구현** | `/admin` 영업 작업대가 **매일 쓰는 도구**로 돌고 있습니다. ⚠️ 기록이 **직원 브라우저(localStorage) 안에만** 있습니다 — 직원이 둘이 되면 서로 안 보입니다 |

| 8 | 알림 · 이메일 연동 | **부분 구현** | 접수가 오면 **슬랙**으로 갑니다 (`INTAKE_WEBHOOK_URL`). 업체 배정 · 견적 제출 · 상태 변경 알림은 **없습니다** |
| 9 | 보안 · 사용자 권한 | **부분 구현** | 역할 넷 · RLS · 상태를 바꾸는 문 하나 · 돈을 확정하는 문 셋까지 **서버에 다 있고 검사됩니다**(92개). DB 가 서야 작동합니다 |
| 10 | 배포 환경 | **정상 작동** | Vercel. `main` 에 합치면 **곧바로 배포**됩니다 — 그래서 작업 브랜치에만 올리고 사장님 "올려" 를 기다립니다 |

### 화면만 존재하는 것 — **없습니다**

이 저장소는 "작동하지 않는 버튼 · 준비 중 자리표시자" 를 금지로
두고 있어서, **누를 수 없는 것은 화면에 내지 않습니다.** DB 가 필요한
구간(`/my` 의 신청 내역 · 업체 대시보드 · 관리자 작업대)은
`auth:false` 인 동안 **한 픽셀도 안 보입니다.**

## 2. 지시서 §3 ~ §9 — 요구한 것 대 지금

### §3 고객 견적 요청

| 항목 | 상태 |
|---|---|
| 서비스 · 업종 · 지역 · 면적 · 예산 · 일정 · 상세 | **정상 작동** |
| **서비스마다 다른 동적 신청서** | **정상 작동** — `js/data/reqforms.js` 12분류 |
| 로그인 없이 신청 | **정상 작동** |
| 스팸 · 중복 방지 | **정상 작동** — 같은 번호 · 같은 상품 · 10분 / 1시간 5건 |
| **고유 요청번호** | **부분 구현** — `SW-AB12-CD34` 발급기와 검사(42개)는 있는데 **DB 에 저장된 뒤에만** 손님께 드립니다. DB 전에는 번호가 안 나갑니다 |
| 요청 상태 확인 | **부분 구현** — `/my` 구간이 붙어 있고 `auth:true` 가 되는 날 저절로 섭니다 |
| **사진 · 파일 첨부** | **미구현** — 받아 둘 저장소가 없습니다 (§10 파일 업로드 방어까지 같이 설계해야 합니다) |

### §4 제휴업체 관리

| 항목 | 상태 |
|---|---|
| 업체 등록 정보(사업자명 · 번호 · 지역 · 업종 · 포트폴리오 · 증빙) | **부분 구현** — 스키마(`provider`)와 공개 화면(`/p/:id`)은 있고 **업체가 직접 적는 화면이 없습니다** (지금은 사람이 `js/data/providers.js` 에 적습니다) |
| 관리자 검토 → 승인 → 활성화 | **부분 구현** — `verified` · `listed` 칸과 "업체가 스스로 못 켠다" 트리거까지 있고 **승인 화면이 없습니다** |
| 배정된 요청 확인 | **부분 구현** — 이번에 `/my` 에 붙였습니다 (DB 가 서면 보입니다) |
| **견적 제안 · 수정 · 철회** | **미구현** — 표 자체가 없습니다. 이번 지시서의 **가장 큰 새 일** |
| 계약 상태 등록 · 완료 내역 | **부분 구현** — 상태 13 · 길 30 · `move_state()` 가 서버에 있고 **버튼이 없습니다** |
| 고객 평가 확인 | **미구현** — 후기 표가 없습니다 |
| 본인 건만 보기 | **정상 작동**(설계) — RLS 가 막습니다. 화면이 아니라 DB 가 막는 쪽입니다 |

### §5 자동 매칭 — **미구현**

지금 있는 것은 **규칙 한 줄**입니다 — `amProviderInCat(p, cat)` 이
"이 업체가 이 분야인가" 를 가릅니다. 지역 · 업종 거르개도 화면에
있습니다. 없는 것은 **접수가 들어왔을 때 서버가 스스로 3~5곳을 골라
배정까지 하는 길**입니다.

⚠️ 지시서가 적은 **"기존 응답률 및 평가"** 는 지금 **잴 수가
없습니다.** 응답 시각을 재는 장치도 후기도 0건입니다 — 없는 값으로
순위를 매기면 그 순간 지어낸 기준입니다. 1차에서는 **카테고리 ·
지역 · 업종 · 승인 상태** 넷으로만 고르고, 응답률은 데이터가 쌓인
뒤에 더하는 것을 권합니다.

### §6 견적 비교 — **부분 구현** (이름이 겹칩니다)

```
지금 있는 /compare  ─ **업체**를 나란히 놓고 봅니다 (분야 · 지역 · 배지)
지시서의 견적 비교  ─ **제출된 견적**을 나란히 놓고 봅니다 (금액 · 범위 · 기간 · A/S)
```

두 화면은 다릅니다. 지금 것은 "업체를 고르는" 자리이고, 지시서가
적은 것은 "받은 견적을 고르는" 자리입니다 — `quote` 표가 없어서
**뒤엣것이 아직 없습니다.**

### §7 관리자 대시보드 — **부분 구현**

| 지시서가 적은 칸 | 지금 |
|---|---|
| 신규 요청 · 매칭 대기 · 응답 대기 · 견적 제출 · 계약 진행 · 완료 · 취소 | 상태 13개 퍼널로 **이번에 붙였습니다** (DB 가 서면 섭니다) |
| 업체 승인 대기 | **미구현** |
| 매출 · 수수료 현황 | 확정 · 청구 · 입금 · **미수금** · **환수**까지 **이번에 붙였습니다** |
| 수동 재배정 · 분쟁 관리 · 공지 관리 · 엑셀 | **미구현** |
| 권한 분리(총괄 / 운영자) | **정상 작동**(설계) — `admin` · `staff` 가 갈려 있고 **돈은 `admin` 만**입니다 |

### §8 알림 자동화 — **부분 구현**

| 때 | 지금 |
|---|---|
| 고객 접수 | **정상 작동** (슬랙) |

⚠️ 알림톡은 **사전 수신동의**가 있어야 보냅니다 (정보통신망법

### §9 수익화 — **부분 구현**

수익모델 여섯 · 수수료 계산(경계값까지 49개 검사) · **정책 사본** ·
환수 · "계약 완료에서 정산으로 바로 가는 길 없음" 까지 **다 있습니다.**
없는 것은 **관리자가 요율을 화면에서 고치는 자리**와 유료 상품 ·
광고 상품의 **판매 화면**입니다.

⚠️ 실제 결제는 지시서 §9 대로 **붙이지 않았습니다.**

## 3. 그래서 1차에서 할 일 — 차례

> ⚠️ **① 이 없으면 ②~⑥ 이 전부 화면만 있는 것이 됩니다.**

| 차례 | 무엇 | 누가 |
|---|---|---|
| **①** | **Supabase 를 세우고 0001~0006 을 돌리는 것** (서울 리전) + Vercel 환경변수 셋 + 방침 수탁자 한 줄 | **사장님** (10분) |
| ② | 로그인 · 가입 화면 (고객 · 업체 공용) — `auth:true` 가 되면 헤더에 섭니다 | 개발 |
| ③ | 업체 등록 화면 + **관리자 승인 화면** (§4) | 개발 |
| ④ | 자동 매칭(카테고리 · 지역 · 업종 · 승인) + 부족하면 관리자 알림 (§5) | 개발 |
| ⑤ | **`quote` 표** — 업체 견적 제출 · 수정 · 철회 + 고객 비교 화면 (§4 · §6) | 개발 |
| ⑥ | 상태 변경 알림 (§8) · 관리자 재배정 · 엑셀 (§7) | 개발 |

⚠️ **②~⑥ 은 새 주소를 거의 안 만듭니다.** `/my` 가 역할을 보고 다른
구간을 내는 방식이라, 로그인 전에는 아무것도 안 보이고 로그인하면
그 사람 것만 섭니다. `/dashboard` · `/partner` 를 따로 만들면 색인은
되는데 들어가면 빈 화면인 주소가 셋 늘어납니다.


## 5. 이 보고서를 쓰면서 **실제로 고친 것**

분석만 하고 끝내지 않았습니다. 지시서 §7 · §4 가 적은 두 화면을
같은 자리(로그인하면 저절로 나오는 구간)에 붙였습니다.

- **업체 대시보드**(§4 · §9-4) — 배정받은 신청(연락처 포함) + 내 계약
- **관리자 작업대**(§7 · §11-2) — 상태 13 퍼널 · 쪽별 · 전환율 +
  계약금액 · 확정 수수료 · 청구 · 입금 · **미수금** · **환수**
- ⚠️ 그러면서 **전환율이 부풀려지는 버그**를 찾았습니다 — 상태 번호만
  보고 자르면 **보류(11)와 취소(10)가 계약(8 이상)으로 집계**됩니다.
  `amDealAfterSign()` 으로 갈랐고 검사를 다섯 넣었습니다.
