## 받은 지시서 (그대로)

### 1. 하단 내비게이션 및 페이지 제목 수정

모바일 하단 내비게이션은 기존 5개 메뉴를 유지합니다.

```
홈 | 팔기 | 구매 | 진행 | 마이
```

각 메뉴를 클릭했을 때 이동하는 페이지의 상단 제목을 다음과 같이
통일합니다.

- "팔기" 클릭 → **"내 폰 판매"**
- "구매" 클릭 → **"내 폰 구매"**

페이지 내부의 주요 실행 버튼은 다음과 같이 구분합니다.

- 판매 신청 버튼: **"내 폰 팔기"**
- 구매 관련 버튼: **"중고폰 구매하기"**

기존 페이지 URL, 라우팅, 기능은 유지하고 표시 문구만 정확하게
수정합니다.

모바일 하단 메뉴의 글자가 잘리거나 아이콘과 겹치지 않도록 확인합니다.

### 2. 필터 선택 시 스크롤 초기화 문제 해결

현재 모바일에서 필터를 선택할 때 페이지가 최상단으로 이동하는 문제가
있습니다. 필터 선택 후에도 사용자가 보고 있던 스크롤 위치가 유지되도록
수정하세요.

적용 대상 — 기기 종류(전체 / 스마트폰 / 태블릿 / 워치 / 이어버즈) ·
제조사(전체 / 애플 / 삼성 / 기타) · 외관 등급 · 기종 검색 ·
가격 및 기타 필터 · 정렬 옵션.

구현 조건

1. 필터 선택 시 해당 필터의 선택 상태만 변경합니다.
2. 페이지 전체 새로고침을 발생시키지 않습니다.
3. 선택한 필터가 화면 최상단으로 강제 이동하지 않도록 합니다.
4. 필터 적용 후 상품 목록만 필요한 범위에서 갱신합니다.
5. 필터 선택 상태를 명확하게 표시합니다.
6. 여러 필터를 연속으로 선택해도 스크롤이 튀지 않도록 합니다.
7. 검색 결과가 변경되더라도 불필요한 자동 스크롤을 실행하지 않습니다.
8. 필터 초기화 버튼은 필터 상태만 초기화하고, 스크롤 이동은 발생시키지
   않습니다.

기술적 점검

- 필터 버튼의 기본 submit 동작 확인
- `href="#"` 로 인한 상단 이동 여부 확인
- 필터 변경 시 라우터의 자동 스크롤 초기화 확인
- 불필요한 `scrollTo(0, 0)` 호출 확인
- 필터 영역 재렌더링 시 스크롤 컨테이너 교체 여부 확인
- URL 쿼리 파라미터 변경 시 페이지 이동 여부 확인
- 비동기 필터 결과 로딩 중 레이아웃 이동 여부 확인

⚠️⚠️ **문제의 원인을 찾아 수정하고, 임시로 스크롤 위치만 복구하는
방식보다 근본적인 해결을 우선합니다.**

### 3. 필터 UI 개선

현재 적용된 프리미엄 오렌지 · 아이보리 · 딥 브라운 디자인을
유지합니다.

- 선택된 필터: 오렌지 배경 + 흰색 글씨
- 선택되지 않은 필터: 밝은 배경 + 진한 브라운 글씨
- 필터 버튼 크기와 간격 통일
- 긴 항목명 줄바꿈 최소화
- 모바일 가로폭에 맞게 필터 배치
- 선택 상태가 시각적으로 명확하게 구분되도록 구현

필터가 여러 줄로 배치되어도 사용자가 현재 선택한 필터 위치를 잃지
않도록 합니다.

## ⚠️⚠️ §2 의 원인 — **찾았습니다** (코드를 읽어서)

사장님이 "임시로 스크롤 위치만 복구하지 말고 근본 원인" 이라고 적으신
그 원인입니다. 세 줄입니다 —

```
① js/pages/phone.js  shopChips() 의 칩이 전부 **<a href="/shop?kd=…">** 입니다
② js/app.js          전역 click 가로채기가 그 링크를 잡아
                     go(href, { keepScroll: a.hasAttribute("data-keep") }) 를 부릅니다
③ js/app.js          render() 의 끝이  if(!RT.keepScroll) window.scrollTo(0,0);
```

칩에 `data-keep` 이 **없으니** `keepScroll` 이 거짓이고, 그래서
**화면을 통째로 다시 그린 뒤 맨 위로 올립니다.** 그게 사장님이 보신
그 현상입니다.

- ⚠️ `href="#"` 은 **한 곳도 없습니다** (기술적 점검 둘째 항목).
- ⚠️ 기본 submit 도 아닙니다 — 찾기 단추는 `type="button"` 이고
  `onclick="shopFind()"` 입니다. 다만 `shopFind()` → `shopGo()` →
  **`go()`** 라 **같은 길**을 지납니다.
- ⚠️ 거르개 초기화(`조건 모두 풀기` · `href="/shop"`)도 **같은 길**이라
  같이 튑니다 (구현 조건 8).
- ⚠️ **스크롤 컨테이너는 안 바뀝니다** — 스크롤하는 것은 `body` 이고
  바뀌는 것은 `#view` 의 `innerHTML` 입니다. 그래서 `scrollTo(0,0)` 만
  없애도 자리는 남습니다. ⚠️⚠️ 다만 **목록이 크게 줄면 문서가
  짧아져서** 브라우저가 스크롤을 깎습니다 — 거기까지 재 봐야 합니다.
- ⚠️ 비동기 로딩이 **없습니다** — 데이터가 스크립트 안에 있어서
  `amShopList()` 가 그 자리에서 셉니다 (그래서 이 저장소는 스켈레톤을
  금지합니다).
- ⚠️ **정렬 옵션은 지금 없습니다.** 지시서가 적었지만 `/shop` 에 정렬
  고르개가 한 개도 없습니다 — **만들면 안 됩니다**: 값 · 등급 ·
  배터리로 줄을 세우면 그 순서가 곧 추천이고, 이 저장소는 "기준을
  밝히지 않은 순서" 를 금지합니다 (약관 제6조 제4항 · `featured` 를
  만들지 않는 것과 같은 까닭). 적을 것은 **"지금 정렬이 없습니다"**
  까지입니다.

### 고치는 길 — 둘이고, **②가 지시서에 맞습니다**

| | 어떻게 | 값 |
|---|---|---|
| ① | 칩에 `data-keep` 을 달기 | 한 줄 · 그래도 `render()` 가 **화면을 통째로** 다시 그립니다 (구현 조건 4 "상품 목록만 필요한 범위에서" 와 어긋납니다) |
| ② | `shopGo()` 가 **주소만 갈아 끼우고**(`pushState`) 칩과 목록만 다시 칠하기 | `pickPaint()` · `rqMctxFee()` 가 이미 그 방식입니다 — 이 저장소가 "적는 칸에서는 다시 그리지 않습니다" 로 여러 번 쓴 길 |

⚠️⚠️ **②로 갈 때 반드시 같이 보세요** —
- **뒤로 가기**가 살아 있어야 합니다. `go()` 를 안 거치면
  `history.replaceState({y})` 도 안 돌아서, 지금의 "뒤로 가면 보던
  자리" 가 조용히 깨집니다 (2026-10-24 에 넣은 것입니다).
- `popstate` 가 `render()` 를 부릅니다 — 칩만 칠하는 길을 만들면
  **뒤로 왔을 때도** 그 칠을 거쳐야 선택 상태가 맞습니다.
- `/sell` 의 기기 카드도 **같은 꼴**(`pwSellGo()` → `go()`)입니다.
  거기도 고치실지는 §2 의 "적용 대상" 에 없으니 **먼저 재 보고**
  정하세요 (그쪽은 고르면 아래 단계가 바뀌는 화면이라 맨 위로
  올라가는 것이 맞을 수도 있습니다).
