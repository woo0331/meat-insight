## C. 개발 계획

### 1순위 — 핵심 흐름 켜기 (새로 만들 것이 거의 없습니다)
고객 선택 → 신청 → 관리자 접수 → 업체 배정 → 업체 상담 → 상태 → 고객 확인 → 완료

| 항목 | 내용 |
|---|---|
| 기존 코드 활용 | **전부 재사용** — 화면 · API · DB · 검사가 이미 있습니다 |
| DB 변경 | 새 표 없음. 운영 DB 판 번호를 확인하고 남은 마이그레이션만 돌림 (`/admin` 1번 칸이 남은 파일 이름을 냅니다) |
| 필요한 승인 | ① 운영 DB 마이그레이션 실행 ② 환경변수 확인(`SUPABASE_*` · `INTAKE_WEBHOOK_URL`) ③ 접수 게이트 열기(quote · close) ④ 첫 관리자 SQL ⑤ 첫 제휴업체 등록 + 계정 연결 ⑥ 사업자 정보 8칸(전자상거래법 제10조) |
| 난이도 | 낮음 (설정 · 확인 위주) |
| 기간 | 승인 후 1~2일 |
| 테스트 | 프리뷰에서 테스트 계정 셋(고객 · 업체 · 관리자)으로 흐름 끝까지 → 운영은 내부 테스트 1건(번호 기록 후 `lost` 처리) · 실제 고객 알림 없음 |

### 2순위 — 업체 스스로 가입 · 연결
| 항목 | 내용 |
|---|---|
| 지금 | 입점 신청 저장 · 직원 등록 · SQL 로 계정 연결 |
| 할 일 | 승인된 입점 신청에 **초대 링크**를 보내고, 그 링크로 로그인하면 계정이 그 업체에 붙는 문 하나 |
| DB 변경 | 있음 (초대 토큰 칸 + 붙이는 함수 1개) |
| 난이도 · 기간 | 중 · 3~4일 |

### 3순위 — 매장 양도양수를 DB 로
| 항목 | 내용 |
|---|---|
| 지금 | 매물이 코드 파일(`market.js`) · 사람이 빌드 |
| 할 일 | `listing` 표(심사 상태 · 거래 상태) · 등록/수정/삭제 문 · 사진(기존 비공개 버킷 방식 재사용) · 문의(기존 `request` 에 매물 id 를 달아 재사용) · 허위 매물 신고 표 · 관리자 심사 칸 |
| 예시 · 실제 구분 | 심사 통과(`listed`)만 공개 · 예시는 지금처럼 따로(`sample.js`) |
| DB 변경 | 있음 (표 2개 + 문 4~5개) |
| 난이도 · 기간 | 중상 · 1~2주 (지금 정적 HTML 로 만드는 매물 상세 · 검색 색인을 DB 로 옮기는 일이 포함) |

### 4순위 — 통계 · 계산도구 연계 보강
기간별 신청 · 배정 · 완료 집계 화면 (DB 변경 없이 조회만) · 계산 결과에서 상담 신청까지 조건 싣기(지금 서비스 고르기까지는 됨). 난이도 낮음 · 2~3일.
