## 2. 복수 선택이 "반쪽" 인 까닭

```
지금 되는 것 ─ 패키지 카드 하나 안에서 상품 체크를 빼고 `/quote?o=a,b,c` 로 넘어감
안 되는 것   ─ ① 패키지 밖의 서비스(분류 26 · 하위 206)는 고를 수가 없습니다
               ② 카드 둘에 걸쳐 고를 수 없습니다 (카드마다 단추가 따로)
               ③ 화면을 떠나면 사라집니다 (주소에만 있고 어디에도 안 남습니다)
               ④ 새로고침하면 사라집니다
               ⑤ 고른 것이 `offers.js` 의 **수익상품 열** 중에서만 됩니다
```

⚠️ `/quote` 는 고른 상품을 `detail["신청 상품"]` **한 줄의 이름 목록**으로
보냅니다. 받는 사람은 읽을 수 있지만 **기계가 항목으로 다루지 못합니다** —
그래서 관리자가 서비스별로 업체를 배정할 수가 없습니다.

## 3. DB 가 "서비스별 배정" 을 못 하는 까닭

```
request   … cat text · offer_id text      ← 신청 하나에 분류 하나
assignment … request_id · provider_id      ← 배정도 신청 단위
```

지시서 §6 의 `QuoteRequestItem` 에 해당하는 표가 **없습니다.** 그래서
"인테리어 → A업체 · 주방설비 → B업체" 가 지금 구조에서는 불가능합니다.

⚠️ 다행히 **손님 데이터가 0건**입니다 (DB 가 아직 환경변수 대기). 그래서
표를 더하는 것이 안전하고 백필이 없습니다.

## 4. 임시저장이 "없음" 인 까닭 — 비슷한 이름에 속지 마세요

| 이름 | 실제로 하는 일 |
|---|---|
| `am.quotes.v1` | **받은 견적을 사장님이 손으로 적어 두는 비교표**입니다. 신청서 초안이 아닙니다 |
| `am.profile.v1` | `/my` 의 상황 · 업종 · 지역 · 평수 |
| `am.saved.v1` | 관심 업체 **id** |

| `am.auth.v1` | 로그인 토큰 |

신청서를 저장해 두고 이어서 쓰는 기능은 **하나도 없습니다.**

## 5. 그래서 이번에 할 것 / 하지 않을 것

**할 것** — 선택 데이터 한 곳(§12) · 복수 선택과 바구니(§3) ·
창업 준비 A~F(§2) · 임시저장(§4) · 통합 신청(§5) · `request_item`(§6) ·
항목별 배정(§7) · 안정성(§8) · 모바일 · 접근성(§13 · §14).

**하지 않을 것과 그 까닭**

- ⚠️⚠️ **`halls.js` 의 차례를 바꾸지 않습니다.** 메인이 `slice(0,6)` 으로
  앞 여섯을 쓰고 있어서, 차례를 바꾸면 **메인이 바뀝니다** — §15 가
  "메인페이지와 다른 전문관 페이지는 이번 작업에서 임의로 변경하지
  않는다" 고 적었습니다. 지시서 §2-B 의 대표 여섯은 **`svcpick.js` 가
  따로** 들고 가리킵니다.
- ⚠️ **분류 · 하위 key 를 새로 만들지 않습니다.** 업체(`subs`) ·
  매물(`sub`) · 글(`cat`) · 업종(`startup`/`closure`)이 전부 그 key 를
  씁니다 — 새로 만들면 등록된 모든 데이터가 조용히 어긋납니다.
- ⚠️ **성함 · 연락처를 브라우저에 담지 않습니다** (§4-1 이 직접 적었고,
  이 저장소도 "가게 컴퓨터는 여러 사람이 씁니다" 로 같은 규칙입니다).
- ⚠️⚠️ **회원 서버 임시저장은 DB 가 서야 돕니다.** 지금 `/api/session` 이
  `auth:false` 라 그 구간이 **한 픽셀도 안 그립니다** — 만들어는 두지만
  "지금 된다" 고 보고하지 않습니다 (절대 규칙 5).
