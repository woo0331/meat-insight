## 4. 데이터베이스 변경 내역

`0009_request_item.sql` — **기존 표를 하나도 안 지웠습니다.**

```
새 표    request_item (request_id · service_id · detail · state)
새 칸    assignment.item_id (null 허용 — 옛 배정이 그대로 유효)
         request.idem (멱등 열쇠 · 부분 unique)
새 문    save_request_items · assign_item · move_item_state · is_my_item
```

- `request.cat` · `offer_id` 는 **그대로 둡니다** — 항목이 있는 신청에서
  `cat` 이 첫 항목을 가리켜 옛 화면 · 옛 질의가 그대로 돕니다.
- **백필이 없습니다** — 손님 데이터가 0건입니다 (환경변수 대기).
- `db/verify.sql` 기대값이 **판 9 · 표 13 · 함수 23** 이 됐습니다.
- ⚠️ **사장님이 Supabase 에서 `0008` · `0009` 를 돌리셔야 합니다.**

## 10. 남아 있는 오류와 미완료 기능

| 무엇 | 왜 |
|---|---|
| **§4-2 회원 서버 임시저장** | 로그인이 `auth:false` 입니다. 서버에 저장하려면 표와 문이 더 필요하고, 지금은 그 길이 없습니다 — 있는 척하지 않습니다 |
| **§13 "한 번에 한 가지 주요 질문"** | 한 화면에 네 걸음으로 두었습니다. 쪼개면 뒤로 가기 · 새로고침에 적으신 것이 날아갑니다 (우선순위가 기능 안정성입니다) |
| **DB 에 실제로 저장되는 것** | `0008` · `0009` 를 돌리시고 Vercel 환경변수를 넣으셔야 합니다. 지금은 접수가 슬랙으로만 갑니다 |
| **실제 업체 배정** | 등록된 업체가 0곳입니다. 배정 화면과 문은 다 있고, 업체를 등록하시면 고르개에 바로 나옵니다 |
| **사업자 정보 여덟 칸** | 비어 있습니다 (전자상거래법 제10조) |
