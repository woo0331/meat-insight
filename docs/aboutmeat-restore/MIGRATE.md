## 4. 옮기는 방법 (개인정보가 공개 저장소에 남지 않게)

- 자료를 **파일로 저장소에 올리지 않습니다** (`woo0331/meat-insight` 는 공개 저장소입니다).
- 세션이 공용 프로젝트에서 `select` 로 읽은 값을 그 자리에서 새 프로젝트에 `insert` 합니다
  (Supabase 연결이 두 프로젝트 모두에 있을 때). 아니면 대표자가 Dashboard → Table Editor →
  Export CSV 로 받아 새 프로젝트에 Import 합니다.
- 다 옮기면 표마다 `count(*)` 와 `md5(string_agg(id::text, ',' order by id))` 를 양쪽에서 맞춰 봅니다.

## 6. 관리자 보안

- 옛 관리자 화면(비밀번호 `meatinsight2024` 가 화면 코드에 있음 · 공개 저장소 이력에 남음)은 **복구하지 않습니다.** 그 비밀번호는 어디에도 재사용하지 마세요.
- 새 관리자는 Supabase Auth 로그인 + `am_admin` 표 + 정책(`am_is_admin()`)으로만 읽고 고칩니다. 로컬 검증: 관리자 아닌 로그인 회원은 상담 신청 0줄 · 상품 수정 0줄, 관리자는 읽기 · 수정 가능, TRUNCATE 는 관리자도 거절.
- service key 는 화면에 싣지 않습니다(서버 함수를 만들 때만 Vercel 환경변수로).
