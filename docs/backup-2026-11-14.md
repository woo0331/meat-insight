## 실행 계획 — Supabase MCP 로 직접 (2026-11-14 확정)

⚠️⚠️ **도구는 한 번 부를 때 보낸 글 전체를 한 덩이로 돌립니다.** 운영에서
`pg_temp` 로만 눌러 봤습니다 —
- 안에 `commit` 이 없으면 **통째로 한 트랜잭션**입니다 (실패하면 그 호출 전체가 되돌아갑니다)
- 안의 `begin … commit` 은 **그대로 지켜집니다** (앞 덩이는 남습니다)
- 그래서 `alter type … add value` 로 더한 값을 **같은 호출 안에서** 쓰면
  `55P04 unsafe use of new value` 로 멈춥니다
- 호출마다 **세션이 새로** 열립니다 (pg_temp 가 안 남습니다)

⚠️ 그래서 `apply-all-*.sql` 조각(20~29만 자)을 통째로 보내지 않고
**마이그레이션 파일 하나 = 호출 하나**로 보냅니다. 파일은 한 글자도 안 바꿉니다.
- `0006_hold_state.sql` 만 **두 번**에 나눕니다 — 21줄(`add value 'hold'`)까지 한 번,
  22줄부터 한 번. 한 번에 보내면 29줄에서 `'hold'` 를 써서 55P04 입니다
- `0015` 는 더한 값을 그 파일 안에서 안 쓰고, `0062` 는 `commit` 으로 이미 갈라 두었습니다

차례: fingerprint(전) → pre-apply → 0001 … 0081 (0006 은 둘로) → post-apply →
verify → list-check → fingerprint(후, 전과 같아야 함)

**같은 방식으로 임시 Postgres 에서 끝까지 돌렸습니다** — 판 81 · post-apply ❌ 0 ·
verify ✅ 14 · list-check ✅ 8 · 기존 16표(실제 이름 · Supabase 기본 권한 재현) 동일.
