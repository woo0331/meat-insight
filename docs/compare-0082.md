⚠️ **S3 와 S4 사이**: 0083 전에는 `assign_more` 가 **비교 배정을 서버에서 거절**합니다

## 3. 복구 — 어느 단계에서 멈췄는지에 따라

| 지금 상태 | 되돌리는 차례 | 결과 |
|---|---|---|
| S1 실패 | 할 일 없음 (한 거래라 안 바뀜) | 0081 그대로 |
| S2 ~ S3 사이 (0082 만) | 필요하면 **R82** 만 | 0081 과 같은 동작 |
| S3 뒤 화면만 되돌리고 싶음 (0083 전) | `compareOn: false` 배포 | 0082 가 있어도 꺼진 화면은 정상(로컬 확인) |
| **S4 뒤 화면을 끄고 싶음** | ⚠️ **R83 먼저** → 그다음 `compareOn: false` 배포 | R83 없이 끄면 꺼진 화면이 표에서 연락처를 물어 **업체 작업실 · 운영자 배정이 빈 채**로 남습니다 |
| S4 뒤 DB 까지 되돌림 | `compareOn: false` 배포 → **R83** → **R82** | 비교 칸 · 자료는 남고 문 · 트리거 · 보기는 내려감 |

- **R83** (`db/migrations/0083_request_contact_lock.sql` 맨 아래 주석):
  `begin; grant select on request to authenticated; delete from schema_version where n = 83; commit;`
- **R82** (`db/migrations/0082_compare_quote.sql` 맨 아래 주석): 문 · 트리거 · 보기를 내리고 판 82 를 지웁니다.
  ⚠️ **칸(`compare` · `blind` · `kind` · `terms`)은 지우지 않습니다** — 비교 요청이 한 건이라도 들어왔으면 그 조건이 사라집니다.
- 두 되돌리기 글은 로컬에서 **주석의 글 그대로** 돌려 봤고, 되돌린 뒤 옛 흐름(요청 → 배정 → 수락 → 견적 → 고르기)과 옛 화면 질의가 되며, 0082 · 0083 을 **다시 올려도** 끝까지 갑니다.

## 3-1. 「끄기」 · 「코드 되돌리기」 · 「DB 되돌리기」는 서로 다릅니다

| 무엇 | 하는 법 | 되돌아가는 것 | 안 되돌아가는 것 |
|---|---|---|---|
| **기능 끄기** | `site.js` 의 `compareOn: false` 로 배포 | 손님 · 업체 화면에서 비교 단추 · 비교표가 사라짐 | **DB 는 그대로**(칸 · 문 · 트리거 · 0083 잠금). 이미 들어온 비교 요청 · 견적 · 동의 기록도 그대로 남습니다 |
| **코드 되돌리기** | 이전 커밋으로 `git revert` 후 배포 | 화면 코드 | DB 그대로. ⚠️ 0083 이 올라가 있으면 옛 코드는 연락처를 표에서 묻다 거절됩니다 → **R83 을 먼저** |
| **DB 되돌리기** | R83 → R82 (아래) | 문 · 트리거 · 보기 · 칸 잠금 | **칸과 자료는 남깁니다**(`compare` · `blind` · `kind` · `terms` 와 그 줄). 기록을 잃지 않는 쪽을 먼저 택합니다 |

⚠️ 운영 중 문제가 생기면 **기능 끄기**가 첫 수입니다(자료를 안 건드립니다). DB 되돌리기는 기능 끄기 뒤에도 문제가 남을 때만.

  - 손님: 동의 없이 고르기 거절 · 남의 요청 거절 · 만료 견적 거절 · 두 번 고르기 거절
  - 연락처: 표에서는 **아무도**(본인도) 못 읽음 · 보기로는 본인 · 운영자 · **고른 업체만** · 고르지 않은 업체는 끝까지 0줄 · 손님이 제공을 거두면 그 순간 0줄
  - 고른 뒤: **고르지 않은 업체는 상태를 못 옮기고 계약을 제 이름으로 못 만듦** · 고른 업체와 계약 → 이용 완료
  - 옛 문이 비교 요청을 건드리면 거절 · 떨어진 견적을 다시 열 수 없음
  - 늦은 응답: 손님이 고른 뒤 들어온 업체는 견적을 못 냄 · 연락처 0줄
  - 선택 뒤 취소: 고른 업체도 그 순간 연락처 0줄 · 단계 이동 · 추가 배정 거절 · **기록은 지우지 않음**
  - 동시에 일어날 때: 배정 · 답 · 견적 · 고르기 문이 전부 그 요청 줄을 **먼저 잠그고**(`for update`) 시작하므로 차례로 처리됩니다 — 고르기가 먼저 끝나면 뒤의 견적 제출은 「이미 상담할 업체를 고르셨습니다」로 거절됩니다
  - Supabase 의 넓은 기본 권한을 그대로 둔 채(pre-apply 를 건너뛴 경우) 올려도 비로그인 실행 0
- **화면** (`tools/test-desk.js` · `test-match.js` — 흉내 서버) 스위치 꺼짐: 오늘과 같은 질의 · 비교 단추 0 / 켜짐: 위 흐름의 단추와 보내는 꾸러미
