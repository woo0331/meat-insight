# 카카오 로그인 KOE205 — 운영에서 오류 재현 · 로그인 미해결

**상태: 운영에서 오류 재현 · 로그인 미해결** (2026-11-11)

사장님이 운영 사이트(storeway.co.kr)에서 카카오 회원가입을 직접 시도하셨고
`kauth.kakao.com` 에서 **KOE205 「잘못된 요청」** 이 다시 떴습니다.
화면 글: 「골프올인원 서비스 설정에 오류가 있어, 이용할 수 없습니다.」

⚠️⚠️ **프런트의 중복 scope 제거는 해결이 아니었습니다.** 2026-11-11 아침에
`js/auth.js` 에서 `scopes` 를 뗀 것은 **중복 한 개를 없앤 것**이 전부이고,
KOE205 는 그대로입니다. 그 작업을 해결로 보고하지 않습니다.

---

## 1. 대조 — 카카오가 받는 scope ↔ 앱에 설정된 동의항목

### 카카오가 실제로 받는 scope (제가 **측정**했습니다)

운영이 쓰는 Supabase 프로젝트의 `/auth/v1/authorize?provider=kakao` 가
돌려주는 302 의 `Location` 을 읽었습니다 —

```
https://kauth.kakao.com/oauth/authorize
  scope = account_email  profile_image  profile_nickname
```

**셋이고 중복이 없습니다.** 이 셋은 **GoTrue(Supabase Auth)가 제 기본값으로
붙이는 것**이고, 우리 코드는 `scopes` 를 한 글자도 안 싣습니다(운영본
`js/auth.js` 에서 확인 — `scopes` 가 걸리는 두 줄은 **주석**입니다).

### 앱에 설정된 동의항목

| 항목 | 앱 설정 | 이 값의 출처 |
|---|---|---|
| `profile_nickname` | 선택 동의 **있음** | ⚠️ **사장님이 콘솔에서 읽어 알려 주신 값** — 제가 못 봤습니다 |
| `profile_image` | 선택 동의 **있음** | ⚠️ 같음 |
| `account_email` | **없음** (비즈 앱이라야 쓸 수 있음) | ⚠️ 같음 + 아래 공식 문서 |

### 문제 항목

> **`account_email`** — 카카오로 **요청은 가는데 앱에는 설정이 없는** 항목.

**근거 셋**

1. 측정 — GoTrue 가 `account_email` 을 늘 보냅니다 (위)
2. 사장님 확인 — 그 항목만 앱에 없습니다
3. 공식 문서 — Supabase 카카오 안내 원문:
   > In the Kakao Developers Portal, the **"account_email" consent item is only
   > available for apps that are registered as "Biz App"**.

⚠️ **아직 못 박지 못한 것** — 이 KOE205 화면에는 **항목 이름이 안 적혀
있습니다**(접힌 「왜 에러가 발생하나요?」 안에 있습니다). 그 글자를 보거나,
제가 드린 시험 링크 넷(`profile_nickname` / `profile_image` /
`account_email` / `openid` 를 하나씩)으로 **어느 것이 KOE205 를 내는지**
확인하면 그때 확정입니다. 지금은 **근거 셋이 한 방향을 가리키는 상태**입니다.

## 2. 공식적으로 지원되는 해결안

### 길 A — Supabase 의 「Allow users without an email」  ⭐ 먼저 재 볼 것

Supabase 카카오 안내 **원문** —

> If you don't need an email address (or `account_email` isn't available for
> your app), you can omit `account_email` and enable **Allow users without an
> email** in the Supabase Kakao provider settings.
>
> If you did not request `account_email` in Kakao, enable **Allow users without
> an email** in the Kakao provider settings.

**누르실 자리**: Supabase 대시보드 → Authentication → Providers →
**Kakao** 펼치기 → **Allow users without an email** 을 **ON** → Save

⚠️⚠️ **이것이 scope 에서 `account_email` 을 빼 주는지는 제가 단정할 수
없습니다.** 문서는 "이메일을 안 받을 때 이 설정을 켜라" 고만 적었지,
"요청하는 scope 가 줄어든다" 고는 안 적었습니다. 둘은 다른 이야기이고 —
scope 가 그대로면 KOE205 도 그대로입니다.

✅ **그런데 이것은 제가 바로 잴 수 있습니다.** 켜신 뒤 말씀만 주시면
authorize 의 302 를 다시 읽어 **scope 에서 `account_email` 이 빠졌는지**를
그 자리에서 보고드립니다. 로그인도 계정 생성도 필요 없습니다.

### 길 B — 카카오 비즈 앱 전환 (이메일 동의항목을 실제로 켜기)

Supabase 안내 원문 —

> To convert your app to a "Biz App", go to **App Settings > App > General**,
> and complete the required fields in the **Business Information** section.

그리고 카카오 공식 문서(개인정보 동의항목) —

> 추가 기능을 신청하려면 아래 작업을 먼저 수행해야 합니다.
> **비즈 앱 전환 신청 자격 확인 · 비즈니스 정보 심사**

⚠️ **사업자등록번호가 반드시 필요한지는 확인하지 못했습니다** — 제가 읽은
두 문서 어디에도 그 말이 **없습니다**. 「비즈니스 정보」 안쪽 화면은
로그인해야 보이고 저는 콘솔을 못 엽니다. — **미검증**

사장님이 이 길을 피하고 싶다고 하셨으므로 **먼저 권하지 않습니다.**

### 길 C — OpenID Connect (ID 토큰)

카카오 OIDC 는 **살아 있습니다** (제가 받아서 확인) —

```
issuer                 https://kauth.kakao.com
token_endpoint         https://kauth.kakao.com/oauth/token
claims_supported       sub · nickname · picture · email
id_token alg           RS256
```

Supabase 안내 원문 —

> Set State to "ON" under **OpenID Connect Activation** on the Kakao Developers
> portal. Add `openid` to scope along with the scope values you wish to obtain
> consent for.

⚠️⚠️ **다만 이 길은 지금 우리 로그인 방식과 다릅니다.** 그 안내는
`auth.signInWithIdToken()` — 즉 **앱이 직접 카카오에서 ID 토큰을 받아
Supabase 에 건네는** 방식이고, 우리는 **주소로 넘겨보내는(redirect) 방식**을
씁니다. 바꾸려면 받는 자리(`amAuthTakeHash()`)와 보내는 자리(`amAuthGo()`)를
새로 써야 하고, 토큰 교환에 **Client Secret** 이 필요해 `api/` 에 서버 쪽
코드가 생깁니다. **작은 일이 아닙니다.**

### 길 D — `api/` 에 서버 측 OAuth 직접

우리가 scope 를 완전히 정합니다(`profile_nickname` 만). Client Secret 은
서버에만 둡니다. 가장 확실하지만 가장 큽니다.

### 길 순서 (제 권고)

1. **길 A 를 켜고 제가 scope 를 잽니다** — 1분, 되돌리기도 1분
2. A 로 `account_email` 이 빠지면 → 사장님이 **한 번 로그인**해 보십니다
3. A 가 scope 를 안 바꾸면 → B(비즈 앱) 또는 C·D 중에서 고르십니다

## 3. 확인하지 못한 설정 (접근 권한 없음)

| 무엇 | 왜 못 봤나 |
|---|---|
| 카카오 앱의 동의항목 설정 화면 | 콘솔은 로그인해야 열립니다. 읽는 공개 API 가 없습니다 |
| 카카오 앱의 OpenID Connect ON/OFF | 같음 |
| 비즈 앱 전환의 정확한 요건 | 같음. 문서에도 세부가 없습니다 |
| Supabase 의 Kakao 공급자 설정 화면 | 관리 API 토큰이 없습니다(요청했다가 거절하셨습니다 — 다시 묻지 않습니다) |
| Supabase 에 Kakao 용 scope 칸이 있는지 | 같음. 문서에도 그런 칸 이야기가 없습니다 |
| 「Allow users without an email」이 scope 를 바꾸는지 | 위 — **켜시면 제가 잽니다** |

브라우저 조작 도구는 **이 환경에 없습니다**(MCP 0개 · Remote Control 폴더
0개). 그래서 콘솔 화면은 사장님만 보실 수 있습니다.

## 4. 보존 — 손대지 않은 것

- **이메일 매직링크 로그인**: 코드 한 줄 안 건드렸습니다. 운영
  `/auth/v1/settings` 에서 `email = true` 확인
- **관리자 UID · 권한**: 아무것도 바꾸지 않았습니다. 역할을 올리는 길은
  0043 의 초대 코드뿐이고, 소셜 로그인으로 들어오는 계정은 `customer` 입니다
- 운영 DB · 배포 · 설정: **하나도 안 바꿨습니다**

## 5. ⚠️ KOE205 를 고쳐도 남는 더 큰 막힘

운영이 가리키는 Supabase 프로젝트(`igignylgzjphtnyxhhsd`)에서 —

- anon 에게 노출된 **표 · 보기가 0개**, **함수가 0개**
- `listing` 을 물으면 `public.listings`, `provider_contact` 를 물으면
  `public.products` 를 제안합니다

0059 · 0064 · 0032 는 공개 보기 셋을 anon 에게 열어 두므로, 마이그레이션이
적힌 대로 올라갔다면 그 목록에 **떠야 합니다.** 안 떴으니 ① 마이그레이션
미적용 ② GRANT 없음 ③ 다른 프로젝트 — **셋 중 무엇인지 아직 모릅니다**
(`docs/access-setup-2026-11-11.md` 3절의 읽기 전용 조회 여섯이 가립니다).

⚠️ **그래서 KOE205 가 풀려도 「회원 생성 · 세션 유지」가 된다고 말할 수
없습니다.** `handle_new_user()`(0005)가 없으면 카카오로 들어오셔도
`account` 줄이 안 생기고, `/my` 가 역할을 못 읽습니다.

## 6. 완료로 보고하는 기준

아래 넷을 **전부** 확인하기 전에는 완료라고 적지 않습니다.

1. ☐ 카카오 authorize 에 가는 scope 에서 문제 항목이 빠졌다 — **제가 측정**
2. ☐ 실제 계정으로 카카오 로그인이 끝까지 갔다 — **사장님 확인 필요**
3. ☐ 그 계정이 `auth.users` 와 `account` 양쪽에 생겼다 — 5절이 풀려야 가능
4. ☐ 새로고침해도 로그인이 유지되고 `/my` 가 열린다 — 2·3 뒤

지금은 **1번부터 막혀 있습니다.**
