## 0. 한 줄로

> **Supabase 가 카카오에 보내는 동의항목 셋은 우리가 못 고칩니다.**
> 카카오 앱에서 **그 셋을 다 켜거나**, 아니면 **다른 방식으로 연결**해야 합니다.

### 그걸 어떻게 아는가 — 증거

사장님 쪽에서 받아 주신 **실제 카카오 인가 요청**이 이것이었습니다.

```
account_email   profile_image   profile_nickname   profile_nickname
```

`profile_nickname` 이 **두 번**입니다.

- 하나는 **Supabase(GoTrue)의 카카오 기본값**
  (`account_email` + `profile_image` + `profile_nickname` — 늘 이 셋을 보냅니다)
- 하나는 **우리가 보낸 것**

즉 우리가 보낸 값이 기본값을 **덮지 않고 뒤에 붙습니다.**
→ **사이트 코드로는 `account_email` 을 뺄 수 없습니다.**

그래서 우리 쪽에서 보내던 줄은 **뗐습니다**(중복만 만들었습니다).
지금 사이트는 `?provider=kakao&redirect_to=...` 만 보냅니다.

# 2단계 — 길 B

## 먼저 하나만 봐 주세요 (3분)

제가 **확인하지 못한 것**이 하나 있습니다. 카카오가 **사업자등록 없이도**
비즈 앱으로 전환하는 길을 열어 두었을 수 있습니다(「개인 개발자 비즈 앱」).
있으면 이 문제가 **그 자리에서** 끝납니다.

```
내 애플리케이션 → (골프올인원 앱) → 「앱 설정」 → 「비즈니스」
```

그 화면에서 **무엇을 요구하는지** 알려 주세요 —

| 보실 것 | 알려 주실 것 |
|---|---|
| 전환 방법이 **몇 가지**인가 | 하나인가, 「사업자」와 「개인 개발자」둘인가 |
| 사업자등록번호 **말고** 다른 길이 있나 | 있으면 그 이름과 요구하는 것 |

⚠️ **아무것도 제출하지 마세요.** 무엇을 묻는지만 보시면 됩니다.

## 그 답에 따라 — 셋 가운데 하나

### 길 B-0 — **사업자등록 없이 되는 길이 있으면** (가장 좋습니다)

그 절차를 따라가시면 됩니다. 끝나면 동의항목에서 **이메일을 「선택 동의」**로
켜시고, `/login` 에서 카카오를 눌러 보시면 됩니다. **코드는 안 바뀝니다.**

### 길 B-1 — **사업자등록이 이미 있으시면**

```
앱 설정 → 비즈니스 → (그 화면이 요구하는 절차) → 심사
심사가 끝나면 →  카카오 로그인 → 동의항목 → 카카오계정(이메일) → 「선택 동의」
```

⚠️⚠️⚠️ **정정 (2026-11-11 저녁)** — 「필수 동의면 거부할 때 로그인이
막힌다 · 선택 동의면 거부해도 들어온다」는 제가 **확인하지 않고 적은
것**입니다. **미검증입니다.**
우리 쪽 코드는 이름이 비어도 버팁니다(`handle_new_user` 가
`nullif(trim(...), '')` 로 받고, 공개 보기가 빈 이름을 「회원」으로 냅니다).
그러나 **카카오가 어떻게 처리하는지는 눌러 봐야 압니다.**

⚠️⚠️⚠️ **정정 (2026-11-11 저녁)** — 「저희는 이메일을 저장하지 않습니다 ·
받아도 버립니다」는 **틀렸습니다.**

맞는 것은 **우리가 만든 `account` 표에 이메일 칸이 없다**는 것뿐입니다.
그 위에 **Supabase 자신의 `auth.users` · `auth.identities`** 가 있고,
공급자가 이메일을 주면 **거기에 담깁니다.** 우리 코드가 안 읽을 뿐
**저장은 됩니다.**

⚠️⚠️ 그래서 **개인정보처리방침에 적어야 합니다.** 지금
`js/data/legal-privacy.js` 에는 **소셜 로그인 줄이 한 줄도 없습니다**
(「카카오」·「소셜」·「구글」·「네이버」를 찾아 0건이었습니다).
방침은 약속이 아니라 **신고서**입니다 — 받으면서 안 적으면 제30조입니다.
**소셜 로그인을 켜는 날 그 줄을 같이 적어야** 합니다.

### 길 B-2 — **사업자등록이 아직 없으시면** → Supabase 로 우회

카카오 기본 연결을 안 쓰고 **Custom Provider** 로 직접 넣습니다.
그러면 **동의항목을 우리가 정하므로** 이메일을 아예 요청하지 않습니다.

⚠️⚠️ **이 길은 네이버도 같이 풉니다.** 네이버는 Supabase 의 기본 공급자
목록에 **없어서**(2026-11-11 에 눈으로 확인했습니다) 어차피 이 칸이
필요합니다. **한 번 보시면 두 공급자의 답이 같이 나옵니다.**

#### ① 먼저 — 그 칸이 **무엇을 묻는지** 봐 주세요

```
supabase.com/dashboard  →  (프로젝트)  →  Authentication  →  Providers
→  목록 맨 아래  「Custom Providers」 또는 「+ New Provider」
```

화면을 찍어 보내 주시면 가장 빠릅니다. 보통 셋 중 하나입니다 —

| 묻는 것 | 그러면 |
|---|---|
| **Discovery URL** 하나 | 아래 ②-ⓐ 로 |
| **Authorization / Token / User Info URL** 셋 | 아래 ②-ⓑ 로 |
| 그런 칸이 **없다** | 그때는 제가 서버 쪽 코드를 씁니다 (**기간은 추정하지 않겠습니다** — 그 칸이 무엇을 요구하는지 보고 적습니다) |

#### ② 넣으실 값 — 카카오

**ⓐ Discovery URL 하나만 묻는 경우**

```
https://kauth.kakao.com/.well-known/openid-configuration
```

**ⓑ 세 개를 따로 묻는 경우**

```
Authorization URL :  https://kauth.kakao.com/oauth/authorize
Token URL         :  https://kauth.kakao.com/oauth/token
User Info URL     :  https://kapi.kakao.com/v2/user/me
```

**둘 다 공통으로 넣으실 것**

| 칸 | 값 | 어디서 |
|---|---|---|
| Client ID | **REST API 키** | 카카오 → 앱 설정 → 앱 키 |
| Client Secret | **Client Secret** | 카카오 → 카카오 로그인 → 보안 → 생성 후 **활성화 ON** |
| Scopes | **`openid`** (칸이 있으면) | — ⚠️ **`account_email` 을 절대 넣지 마세요** |
| Callback (Redirect) URI | Supabase 가 보여 주는 주소 | 그대로 복사해 **카카오의 Redirect URI** 에 추가 |

⚠️⚠️⚠️ **키 값을 채팅에 붙여 넣지 마세요.** 카카오 화면에서 복사해
Supabase 칸에 **바로** 넣으십니다. 저는 그 값을 받지 않습니다.

⚠️ 카카오 쪽에 **OpenID Connect 활성화가 ON** 이어야 합니다
(이미 켜 두셨다고 하셨습니다).

#### ③ 그리고 — **제게 한 줄만 알려 주세요**

Custom Provider 를 저장하면 Supabase 가 그 공급자에 **이름(키)**을 붙입니다.
`kakao` 일 수도 있고 다른 글자일 수도 있습니다.

```
그 값을 어디서 보나:
  https://<프로젝트>.supabase.co/auth/v1/settings  를 브라우저로 열고
  "external" 안에서 true 인 이름을 찾습니다
```

⚠️⚠️ **그 이름이 `kakao` 가 아니면 사이트 코드를 한 줄 고쳐야 합니다.**
화면은 `AM_SOCIAL` 의 키로 「켜졌나」를 묻는데, 이름이 다르면 **단추가
아예 안 뜹니다**(에러도 안 납니다). 그 한 줄은 제가 고칩니다.

> ⚠️ 제가 2026-11-11 낮에 「코드 0줄」이라고 말씀드린 것을 **정정합니다** —
> 코드를 읽어 보니 키로 거르고 있었습니다. **한 줄입니다.**

## 3단계 — 바꾸신 뒤 **되는지 보는 법** (중요합니다)

> ⚠️ **이걸 안 하면 「고쳤다」를 아무도 증명 못 합니다.**
> 저는 사이트에 못 나가므로, 이 확인은 사장님만 하실 수 있습니다.

### 가장 쉬운 길 — 오류가 나면 **주소창을 복사**

1. `https://storeway.co.kr/login` 을 엽니다
2. **카카오 로그인**을 누릅니다
3. **KOE205 화면이 뜨면** — 그 화면의 **주소창을 통째로 복사**해서 보내 주세요
   (`kauth.kakao.com/oauth/authorize?...scope=...` 가 들어 있습니다)
4. **로그인이 되면** — 됐습니다. 아래 「되고 나서 볼 것」으로 갑니다

### 더 확실한 길 — 크롬 개발자 도구

```
F12  →  「Network」 탭  →  「Preserve log」 체크
→  카카오 로그인 클릭
→  목록에서 kauth.kakao.com 으로 가는 줄을 찾아 클릭
→  Headers 의 Request URL 을 복사
```

그 주소의 `scope=` 뒤에 무엇이 들어 있는지가 **답**입니다.

### 되고 나서 볼 것 — 이것까지 봐야 「완료」입니다

| # | 볼 것 | 어떻게 |
|---|---|---|
| 1 | 로그인 뒤 **원래 보던 화면**으로 돌아오는가 | 눈으로 |
| 2 | **새로고침해도** 로그인이 유지되는가 | F5 |
| 3 | 다른 화면으로 가도 유지되는가 | 메뉴 눌러 보기 |
| 4 | **로그아웃**이 되는가 | 머리말에서 |
| 5 | 두 번째 로그인 때 **계정이 또 생기지 않는가** | Supabase → Authentication → Users 에서 줄 수 |
| 6 | 그 카카오 계정이 **관리자가 아닌가** | `/admin` 에 들어가지면 안 됩니다 |
| 7 | **기존 이메일 로그인이 그대로 되는가** | `/login` 에서 메일 주소로 |

## ⚠️ 꼭 지켜 주실 것

| | |
|---|---|
| **키를 채팅에 붙여 넣지 마세요** | REST API 키 · Client Secret 은 **Supabase 칸에 직접** 넣으십니다. 저는 안 받습니다 |
| **기존 이메일 로그인 칸을 지우지 마세요** | 카카오가 **완전히** 될 때까지 |
| **관리자 계정을 손대지 마세요** | 지우거나 다시 만들지 않습니다 |
| **카카오로 들어온 계정에 관리자를 주지 마세요** | 새로 들어온 계정은 전부 일반 회원입니다 |

### ⚠️⚠️⚠️ 그리고 가장 중요한 것

**이메일 로그인 칸을 없애기 전에 `db/README.md` 의 §1-4c 를 꼭 보세요.**

관리자 권한이 **특정 계정 하나에 묶여** 있습니다. 카카오로 들어오시면
**다른 계정**이 생기고 그 계정은 일반 회원입니다. 이메일 칸을 먼저
없애시면 **`/admin` 에 영영 못 들어가십니다.**

차례는 그 글에 적어 두었습니다 — ① 소셜로 먼저 들어가고 ② 그 계정 번호를
찾아 ③ SQL 한 줄로 관리자로 올리고 ④ `/admin` 이 열리는지 보고 ⑤ **그
다음에야** 이메일 칸을 뺍니다.

| | |

⚠️ 다만 **운영에 Supabase 환경변수가 없으면** 로그인 화면이 「준비 중」
셋으로만 보입니다. 그 둘(`SUPABASE_URL` · `SUPABASE_ANON_KEY`)이
Vercel 에 들어가 있고 **다시 배포**되었는지부터 확인하세요 —
`https://storeway.co.kr/api/session` 을 열어 `"auth":true` 면 켜진 것이고,
`"auth":false` 면 **비어 있는 변수 이름을 그 자리에서 말해 줍니다.**
