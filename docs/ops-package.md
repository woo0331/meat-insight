## 3. 이미지 전체 해석 — 도입안 먼저 (`docs/image-lib-decision.md`)
- **권하는 길: A** — `package.json` 을 새로 만들고 공식 npm 패키지 `jpeg-js@0.4.4`(BSD-3) 하나를 의존성으로 추가해,
  저장 완료 검사에서 JPG 를 **전체 해석 · 다시 인코딩**(해석 한도 5MP · 64MB)합니다. 승인 문장은 그 문서 4장.
- 막힌 정확한 까닭: 이 세션에서 `npm pack` 으로 받은 그 패키지 파일을 **저장소 안(`api/_vendor/`)에 복사**하려던 명령이
  세션의 권한 확인에서 「바깥 코드를 승인 없이 저장소에 들여오는 일」로 거절됐습니다. 우회하지 않았고 남은 파일은 없습니다.
- 지금(도입 전) 서버 검사는 **머리 · 끝만** 봅니다 — 전체 해석과 다릅니다. 운영 사진을 켜기 전에 A 를 하거나, 한계를 받아들인다고 정해 주세요.

## 5. 사진 업로드 실제 확인 절차 (운영 · 승인 뒤)
1. 일반 회원으로 로그인 → `/cat/used` → 「판매글 등록」 → 폰 사진 2장 고르기 → 미리 보기 · 대표 바꾸기 → 등록.
2. 목록 카드에 **작은 사진**이 뜨는지(개발자 도구 Network 에서 `….t.jpg`), 상세에 큰 사진이 뜨는지.
3. `/my` 「내 판매글」에서 사진 하나 빼기 → 목록 · 상세에서 사라지는지.
4. 위치정보: 올린 사진의 공개 주소를 받아 EXIF 보기 도구로 열어 GPS 가 없는지.
5. 시험 매물은 **내리기**(가짜 매물을 남기지 않습니다).
