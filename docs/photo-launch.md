# 매물 사진 켜는 순서 · 중단 조건 (2026-11-17)

⚠️ 이 문서의 단계는 **아직 하나도 실행하지 않았습니다.** 운영 DB · 버킷 · 환경변수는 승인 뒤에만 바꿉니다.
⚠️ **출시 차단 항목** — 0084 를 올리기 전에는 사진 업로드를 운영에서 켜지 않습니다. 0084 전에는 서버의
저장 완료 검사를 **건너뛰는 직접 호출**(업로드 주소만 받고 확인을 안 부르는 것)로 올린 파일이 그대로 공개됩니다.

## 왜 0084 앞에 0082 · 0083 이 와야 하나 (내용은 서로 상관없는데도)

이 저장소의 DB 는 **번호 하나로 어디까지 됐는지를 셉니다** —

- 마이그레이션마다 끝에서 `schema_version` 에 제 번호를 적습니다(`insert … values (84, …)`).
- `db/resume.sql` 은 **`max(n)` 하나**로 "다음에 붙여 넣을 번호" 를 정합니다(`max(n) + 1`). 빠진 번호를 찾지 않습니다.
- 붙여넣기 조각(`db/apply-*.sql`)은 "바로 앞 조각까지 끝낸 DB 에만" 쓰도록 만들어져 있고,
  `tools/test-upgrade.js` · `tools/sql/stage.js` 도 번호 차례대로 올린 DB 만 재 봅니다.

그래서 0084 를 먼저 올리면 `max(n)` 이 84 가 되어, 다음에 `resume.sql` 을 돌리는 사람에게 **"84 까지 끝났습니다"**
로 보이고 0082 · 0083 이 **말없이 빠진 채** 남습니다. 비교견적 단계 검사(`db/compare-check.sql`)도 81 → 82 → 83 을
전제로 합니다.

**그래서 번호를 건너뛰어 올리지 않습니다.** 사진을 비교견적보다 먼저 켜야 한다면 방법은 둘이고, 둘 다 승인이 필요합니다 —
① 0082 · 0083 을 먼저 올린다(**compareOn 은 false 그대로** · 비교견적은 켜지 않음) — 0082 는 더하기만 하고
0083 은 화면이 이미 보기로 읽게 바뀌어 있어(135cdf487) 지금 화면이 깨지지 않습니다.
② 번호를 다시 매긴다(0084 → 0082, 비교견적을 0083 · 0084 로) — 이미 승인 문서에 번호가 적혀 있어 권하지 않습니다.

**사진 준비와 비교견적 켜기는 따로입니다.** 0082 · 0083 을 올려도 `compareOn` 은 별도 승인 전까지 false 입니다.

## 서버가 보는 것 · 못 보는 것

- 보는 것(저장 완료 단계): 주인 · 8MB · JPG 만 · 첫 바이트 · 머리(가로 · 세로 · 픽셀 수) · 끝 표시(잘린 파일) · EXIF/XMP.
  작은 사진(목록 카드용 480px)도 같은 검사를 더 좁게 합니다.
- **못 보는 것**: 그림 **전체 해석**(디코딩). 머리 · 끝은 멀쩡하고 몸통만 깨진 JPG 는 통과합니다(검사에 명시).
  브라우저는 canvas 로 전체를 그려 다시 만든 파일만 보내므로 정상 경로는 해석된 파일입니다.
  서버에서도 전체 해석 · 재인코딩을 하려면 JPEG 라이브러리(예: jpeg-js · BSD)를 저장소에 들여와야 해서
  **승인을 받아야 합니다**(이번에는 들이지 않았습니다).
- 정리: 실패한 **새 사진**을 지울 때는 그 사진 줄에서 지은 경로(큰 파일 · 작은 파일)만 지웁니다. 이미 저장된 사진은
  저장 완료 단계에서 다시 검사하지도 · 지우지도 않습니다. 빼기는 문이 성공한 뒤에만 그 줄의 파일을 지웁니다.
