## 2. 운영 적용 · 검사 · 복구

1. 앞 단계(0082 · 0083 · 0084)를 `docs/photo-launch.md` 대로 끝낸 뒤 — `select max(n) from schema_version` = 84
2. `db/pre-apply.sql` → `db/apply-0085.sql` → `db/post-apply.sql`
3. 확인(읽기만):
   ```sql
   select max(n) from schema_version;                                                  -- 85
   select count(*) from information_schema.columns where table_name = 'teetime' and column_name in
     ('price_unit','cart_rule','apply_until','cancel_terms','course_sub','min_players'); -- 6
   select has_function_privilege('anon', 'set_teetime_state(jsonb)', 'execute');        -- false
   select has_table_privilege('anon', 'v_teetime_pv_stats', 'select');                   -- false
   ```
4. 화면 확인: 업체 계정으로 `/desk` → 「새 자리 올리기」에 가격 단위 · 취소 조건 칸이 보이는지
5. **멈출 때**: 위 값이 하나라도 다르면 멈추고 알려 주세요. 되돌리기는 0085 파일 끝 주석(칸 · 줄은 남김).

## 3. 손님 화면에 반영되는 길

티타임 · 신청은 **실시간**입니다 — 브라우저가 `v_teetime_open` · `v_teebook_mine` · `v_teebook_pv` 를 그때그때 읽으므로
업체가 올리거나 바꾸면 운영자가 다시 배포할 일이 없습니다.
다만 **업체 정보 · 가격표 · 시설 사진 · 후기 · 골프장 정보**는 빌드 때 HTML 에 찍히므로 `tools/pull-providers.js` ·
`pull-reviews.js` · `pull-courses.js` 를 돌리고 다시 배포해야 바뀝니다 — 개선안: `/pro/<id>` 와 분류 목록이 페이지를 연 뒤
`v_provider_card` · `v_provider_price_public` · `v_provider_photo_public` 을 한 번 더 읽어 **바뀐 값만 덮어쓰기**(크롤러용 HTML 은 그대로 두고).
이 보기들은 이미 있고 비로그인에게 열려 있어 DB 변경이 필요 없습니다(다음 작업 후보).

## 4. 외부 재고의 한계

다른 채널(전화 · 다른 사이트)에서 팔린 자리는 **저희가 자동으로 알 수 없습니다.** 업체 작업실에 「직접 마감해 주세요」를
적어 두었고, 마감은 확정 예약을 건드리지 않습니다.

## 5. 수익화 준비 — 설계안만 (과금 기능은 만들지 않음)

- 지금 세는 것(운영자 집계): 업체별 올린 자리 · 신청 · 확정 · 거절 · 손님 취소 · 업체 취소 · 양쪽 이용 표시 · 확인 필요 · 미확인.
  **금액은 세지 않습니다** — 그린피는 업체와 손님 사이의 값이고 플랫폼 매출이 아닙니다. 업체의 「이용함」 하나로 수수료를 만들지 않습니다.
- 최초 유입 경로: 지금 기록하지 않습니다(신청 줄에 담으려면 칸과 방침 수집 항목이 같이 늘어야 합니다 — 결정 필요).
- 과금을 붙일 때 필요한 구조(설계):
  1. **요율 표** `fee_plan(id, kind: 월정액/건당/무료, rate, unit, effective_from, effective_to)` — 바꾸지 않고 새 줄로(버전).
  2. **업체 동의** `fee_consent(provider_id, plan_id, agreed_at, by_user)` — 동의 없는 업체에는 청구하지 않음.
  3. **건별 근거** — 청구 대상은 「양쪽 이용 표시」 또는 업체 확정 후 일정 기간 이의 없는 건 등 **정책으로 정한 상태**만, 신청 줄 id 와 요율 버전을 같이 기록.
  4. **취소 · 조정** — 업체 취소 · 분쟁 · 환불은 음수 조정 줄로(지우지 않음). 기존 `confirm_fee` · `clawback_fee`(0003)와 같은 결.
  5. 사이트에 요금 · 무료 기간을 공지하는 것은 정책이 정해진 뒤 — 지금은 어느 화면에도 적지 않습니다.
- PG · 자동청구 · 정산 · 예치금은 이번에 만들지 않았습니다. 과금이 없어도 예약 관리는 그대로 돕니다.
