# 카카오 알림톡 신청 — 그대로 따라 하면 되는 순서

요청이 올라와도 업체가 모르면 견적이 안 옵니다. 알림톡은 그걸 메우는
가장 확실한 길인데, **심사에 2주쯤 걸립니다.** 그래서 코드보다 신청이
먼저입니다. 아래 1~3번을 이번 주에 걸어 두시면 됩니다.

코드 쪽은 다 되어 있습니다 (`tools/notify-send.js` · `db/phase8_notify.sql`).
심사가 끝나기 전에도 **문자로는 바로 나갑니다** — 같은 계정, 같은 코드입니다.

---

## 1. 대행사 가입 (하루면 됩니다)

솔라피(solapi.com) 기준으로 적었습니다. 알리고·NHN 등도 같은 구조라
`tools/notify-sources.js` 의 `SEND` 블록만 바꾸면 됩니다.

1. 가입 → **발신번호 등록** (사업자등록증 + 통신서비스 이용증명원)
   - 여기서 등록한 번호로만 문자가 나갑니다. 며칠 걸립니다.
2. **API 키·시크릿 발급**
3. 충전 — 문자 건당 20원 안팎, 알림톡 건당 8~15원

## 2. 카카오 비즈니스 채널 (며칠)

1. [비즈니스 카카오](https://business.kakao.com) 에서 **채널 만들기**
2. **비즈니스 인증** (사업자등록증)
3. 대행사 콘솔에서 **발신프로필 등록** → `ALIMTALK_PFID` 를 받습니다

## 3. 템플릿 심사 (여기가 2주)

대행사 콘솔에서 아래 **세 개**를 그대로 등록합니다.
글자 하나라도 다르면 발송이 거절되니 복사해서 붙여넣으세요.

> 왜 셋만? 심사는 템플릿마다 따로 받습니다. 요청·견적·선택 셋이
> 매칭의 전부이고, 나머지(대화·당일알바)는 나중에 추가하면 됩니다.

### ① 새 요청 등록 안내 — `ALIMTALK_TPL_REQUEST`

```
[고리] 새 요청이 등록되었습니다

▪ 분야 : #{분야}
▪ 지역 : #{지역}
▪ 내용 : #{내용}

요청 내용을 확인하고 견적을 보내실 수 있습니다.
```
- 버튼: **웹링크** / 이름 `요청 확인하기` / 주소 `#{링크}`

### ② 견적 도착 안내 — `ALIMTALK_TPL_QUOTE`

```
[고리] 견적이 도착했습니다

▪ 요청 : #{요청}
▪ 내용 : #{내용}

받으신 견적을 비교해 보실 수 있습니다.
```
- 버튼: **웹링크** / 이름 `견적 확인하기` / 주소 `#{링크}`

### ③ 견적 선택 안내 — `ALIMTALK_TPL_SELECTED`

```
[고리] 보내신 견적이 선택되었습니다

▪ 요청 : #{요청}

요청자와 연결되었습니다. 세부 조건을 협의해 주세요.
```
- 버튼: **웹링크** / 이름 `거래 확인하기` / 주소 `#{링크}`

### 반려당하는 흔한 이유

- **광고성 문구** — "지금 가입", "할인", "이벤트", "혜택" 이 들어가면
  정보성으로 안 봐 줍니다. 위 문구에는 하나도 없습니다.
- **치환자만 있는 줄** — `#{내용}` 만 덩그러니 있는 줄은 반려됩니다.
  위 문구는 전부 `▪ 항목 : ` 이라는 고정 문구를 달고 있습니다.
- **발신자를 안 밝힘** — 그래서 전부 `[고리]` 로 시작합니다.

`test/notify-e2e.js` 의 4번이 이 셋을 자동으로 지킵니다. 문구를 고치면
테스트가 먼저 잡아 줍니다.

## 4. 켜기

### 4-1. DB 준비 (한 번)

Supabase → SQL Editor 에 `db/phase8_notify.sql` 을 통째로 붙여넣고 실행.

기존 표는 칸 하나도 안 바뀝니다. `notify_outbox` 한 개가 생기고,
`notifications` 에 행이 생기면 거기 같이 쌓이는 트리거가 붙습니다.

> **밤에는 안 보냅니다.** 21시~08시에 생긴 알림은 트리거가 아침 8시로
> 미뤄 둡니다. 새벽에 울리면 사장님은 알림을 꺼 버립니다.

### 4-2. Secrets 등록

저장소 → Settings → Secrets and variables → Actions

| 이름 | 값 | 언제부터 |
|---|---|---|
| `SUPABASE_URL` | `https://xxxx.supabase.co` | 지금 |
| `SUPABASE_SERVICE_KEY` | service_role 키 | 지금 |
| `SOLAPI_KEY` · `SOLAPI_SECRET` | 대행사 API 키 | 1번 끝나면 |
| `SOLAPI_FROM` | 등록한 발신번호 | 1번 끝나면 |
| `ALIMTALK_PFID` | 발신프로필 키 | 2번 끝나면 |
| `ALIMTALK_TPL_REQUEST` · `_QUOTE` · `_SELECTED` | 승인된 템플릿 id | 3번 끝나면 |

⚠️ **`service_role` 키는 RLS 를 지나칩니다.** 이 키가 새면 데이터를
통째로 지울 수 있습니다. Secrets 에만 두고, 저장소 파일·화면 소스에는
절대 넣지 마세요.

`ALIMTALK_*` 가 없어도 돌아갑니다 — 그동안은 문자로 나갑니다.

### 4-3. 확인

Actions 탭 → **알림 내보내기** → Run workflow.

15분마다(08~21시 KST) 저절로 돕니다. 밤에는 아예 안 돕니다.

## 지금 확인 안 된 것

개발 환경에서 `api.solapi.com` 이 막혀 있어(403) **실제 발송은 한 번도
확인하지 못했습니다.** 축평원 때와 같습니다 — 추측한 응답 모양을
"된다" 고 말하지 않겠습니다.

키를 넣고 아래를 한 번 돌려서 출력을 보내 주시면, 모양이 다를 경우
`tools/notify-sources.js` 의 `SEND` 블록만 고치면 됩니다.

```bash
node tools/notify-send.js --probe   # 보낼 내용만 (안 보냄)
node tools/notify-send.js --dry     # 본문까지 (발송만 안 함)
```
